# Правила работы Codex

## Граница проекта

Это самостоятельный исследовательский проект. Его исследовательские задачи определяются согласованной с пользователем целью и границей проекта.

Документация и отчёты ведутся на русском языке. Репозиторий хранит проверяемые материалы и состояние работы. Текущее состояние фиксируется в `docs/current-state.md`.

## Автономное исследование

Codex самостоятельно исследует, реализует и проверяет гипотезы в согласованной исследовательской границе. Архитектура, технологии, механизм и модель данных заранее не предписаны. До согласования исследовательской цели научную работу не начинать.

Каждый исследовательский шаг должен быть конечным: указать вопрос, способ проверки, критерий завершения и предел ресурсов. Шаг может завершиться анализом, экспериментом или документацией; реализация кода не обязательна.

Различать гипотезы, наблюдаемые результаты и принятые решения. Сохранять отрицательные результаты и ограничения выводов. Для воспроизводимости фиксировать исходные данные или их источник, версии среды, команды, параметры и критерии оценки в объёме, достаточном для повторения проверки.

Короткие ADR создавать только для значимых решений: контекст, решение, рассмотренные альтернативы и последствия. Не создавать ADR для ещё не принятых решений.

Не подменять исследуемый механизм готовой LLM или её ответами. Если LLM используется как вспомогательный инструмент, обозначить её роль так, чтобы результат проверки механизма оставался самостоятельным и воспроизводимым.

Не повторять без изменений неудачные попытки. При отсутствии прогресса зафиксировать причину, изменить способ проверки либо завершить направление с объяснением.

## Checkpoint и восстановление

После значимого checkpoint проверить материалы подходящим способом, обновить документацию и текущее состояние, выполнить `git diff --check`, затем сделать commit и push в рабочую ветку. Если проверка или push невозможны, зафиксировать причину и незавершённое действие.

Состояние должно восстанавливаться по Git и файлам без истории чата: выполненная работа, доказательства, нерешённые вопросы и следующий конечный шаг должны быть понятны из репозитория. Не выдавать непроверенную гипотезу за результат или решение.

## Ограничения

Не выполнять merge в main. Изменения готовить в отдельной ветке; перед merge требуется external review.

Не выполнять разрушительные операции вне проекта. Не использовать платные сервисы без разрешения пользователя. Обращаться к пользователю при необходимости человеческого семантического суждения, изменении цели, превышении согласованных ресурсов или рискованном действии; обычные обратимые действия внутри согласованной границы выполнять самостоятельно.
