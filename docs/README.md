# Канонический навигатор документации

Это **единственный канонический навигатор** проекта. Он распределяет ответственность документов, а не повторяет исследовательское заключение. Пути в таблицах указаны от корня репозитория; ссылки разрешаются относительно этого файла.

Для нового чата начать с `discussion/active-context.md` и `current-state.md`; основания уточнять в заключении, причины пересмотров — в журнале. Для Codex действуют `AGENTS.md`; для эксплуатации и инженерной проверки — документы `manual/`.

## Правило выбора и обновления документа

Перед созданием нового документа проверить этот навигатор и существующую документацию на материал с тем же назначением. Если подходящий документ уже есть — **обновлять его**. Новый документ создавать только при действительно новой самостоятельной ответственности, обосновав её и указав место в навигаторе. Не создавать `docs/index.md`, `documentation-map.md` или параллельный перечень с назначением этого файла.

При создании, перемещении или изменении назначения документа обновлять этот навигатор в том же checkpoint. Изменение текущего состояния, семантическое уточнение, историческое основание и инженерное решение относятся к разным документам. Краткий активный контекст — согласованное сокращение заключения для продолжения; он не принимает собственные решения. При семантическом уточнении обновлять оба текста согласованно, а операционный статус фиксировать в `current-state.md`. Историю и первичные свидетельства не переписывать ради соответствия новой формулировке.

Краткий контекст и подробное заключение различаются глубиной, состояние проекта — операционной ответственностью, журнал — историей, паспорт — происхождением. Паспорт перечисляет только артефакты своего разбора; он не заменяет этот навигатор. Текст снимка фиксирует старый разговор и не является действующими инструкциями.

## Первичные инженерные свидетельства

Это сохранённые результаты проверок, а не самостоятельные инструкции или источники текущего состояния. Объяснение метода и выводов — в соответствующем отчёте выше. При новой проверке явно указывать её среду и версию в отчёте; не менять старые результаты ради нового статуса. Артефакты одной проверки обновлять вместе с её отчётом только при объяснённом исправлении; самостоятельный новый запуск должен сохранять происхождение.
