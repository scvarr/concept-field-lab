### Воспроизведение актуальной проверки

Из корня проекта, без установленного браузерного тестового пакета:

```bat
python -m scripts.verify_stone --output local-data/stone-k001/recheck.json
python -m unittest discover -s tests -v
python -m compileall -q app scripts tests
node --check app/static/app.js
git diff --check
```

Предметная программа создаёт собственную временную базу **внутри проекта**; текущий граф/свидетельства не переписывает. Проверяет сохранённые ID и историю именно канонического артефакта. Чтобы открыть его в редакторе: запустить `python -m app.server --port 8771 --db local-data/stone-k001/workspace.sqlite3`; если база новая, «Обмен и кандидаты» → «Файл JSON» → `data/experiments/stone/stone.json` → preview → очередь → просмотр/принятие 58 объектов. Это техническое принятие записи, не подтверждение её смысловой истинности. После перезагрузки открыть исследование; пути просмотра не сохраняются, данные сохраняются.

Воспроизвести **построение формы**, получая новые UUID, можно в новой собственной базе:

```bat
python -m scripts.stone_decomposition baseline --db local-data/stone-replay/workspace.sqlite3 --output local-data/stone-replay/baseline.json
python -m scripts.stone_decomposition expand --db local-data/stone-replay/workspace.sqlite3 --output local-data/stone-replay/expanded.json
python -m scripts.stone_decomposition prune --db local-data/stone-replay/workspace.sqlite3 --output local-data/stone-replay/stone.json --evidence local-data/stone-replay/audit.json
```

`baseline` требует пустой базы, `expand` и `prune` не предназначены для безусловного повторения на уже пересмотренной структуре. Точная история GUI первого прохода не воспроизводится этим сокращённым маршрутом; она сохранена в итоговом JSON. Для продолжения с прежними ID следует импортировать артефакт, а не генерировать новый. Скрипты используют штатные `Store`/`graph_export`; обхода модели данных и нового редактора нет.

### Отрицательные попытки и пределы автоматизации

Первое обращение к 8771 было выполнено до запуска сервера и получило отказ соединения; после запуска прошло. При нажатии удаления пробной α команда браузера получила таймаут; следующая попытка чтения старой вкладки тоже. Новая вкладка работала, позже база показала удаление в версии 172. Предохранительный программный cleanup обнаружил отсутствие α и отказался от повторной мутации. Причина задержки/завершения не установлена; это не воспроизведённый дефект модели или удаления редактора.

Playwright `fill` менял видимое число глубины, но ожидаемый вид сразу не применялся. Обычные клавиши с Tab применили глубину 1 и показали 9/29 элементов / 8 связей; в итоговом снимке именно этот вид. Ошибку редактора по одному способу автоматизации не заявляем.

Нажатие GUI «Экспорт исследования» выполнено, но событие `download` не получено за 10 с. Граф остался 29/28, error/warn логи двух проверочных страниц пусты; полученный браузером файл **не проверен**. Программный `graph_export` и его обратный импорт проверены. Полную проверку GUI-скачивания оставляем отдельному операторскому проходу; иной браузер и обходы скачивания в этом задании не исследовались. Это единственный непроверенный исход обмена GUI; канонический JSON уже существует и принят GUI-импортом.

Первая новая браузерная проверка посчитала ожидаемый HTTP 400 JavaScript-ошибкой; тест исправлен так, чтобы отдельно проверять ровно один ожидаемый отказ и отсутствие иных ошибок. Для генератора большого JSON увеличен ограниченный буфер subprocess до 16 МиБ: стандартный буфер был меньше документа, приложение здесь не участвовало. Benchmark сначала вызван как файл и не нашёл пакет `app`; корректная команда — `python -m scripts.benchmark_workbench`.

Визуальная проверка обнаружила растягивание SVG на десятки тысяч пикселей при большом составе: процентная высота не имела ограниченного контейнера. Панель получила фиксируемую по окну высоту; обзор состава ограничен 14 компонентами в двух колонках, выбранный компонент включается обязательно. Полные данные доступны поиском и страницами. Добавлены проверки высоты, выполнены повторно оба браузерных сценария. Это инженерное ограничение отображения, не ограничение глубины или размера данных. Дополнительная проверка быстрого последовательного импорта выявила гонку отрисовки очереди: выбор мог выполняться до завершения её загрузки. Теперь действия очереди недоступны во время загрузки, устаревшие ответы не применяются. После этого повторно прошли оба браузерных сценария.

## Граница результата

Операторские действия доступны без изменения кода / JSON-файлов. Семантическую эквивалентность и выбор переносимых утверждений решает человек. Инструмент переносит все показанные ссылки на целое только после подтверждения; неоднозначные случаи не угадывает. Локальная отмена требует неизменного затронутого контекста, включая соответствия исследования; иначе доступна полная история. В импортированном фрагменте контекст замещения может включать объекты вне фрагмента: это сохраняет происхождение, но не обещает локальную отмену без полного графа. Обратный diff не стирает накопленные origins.

Путь навигации живёт только во вкладке и начинается заново после её перезагрузки. Производительность сверх 5 000 узлов / 10 000 связей и 2 000 компонентов здесь не измерялась. Долгосрочное удобство ежедневной работы требует external review оператором; автоматические сценарии не заменяют такую оценку. Семантический вывод, поиск маршрутов, активация, обучение и генерация не реализованы.
