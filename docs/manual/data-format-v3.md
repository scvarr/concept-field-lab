# JSON v3: накопительные исследования

Расширение [v2](data-format-v2.md), без изменения исходных K001/K002. Приложение экспортирует `format: concept-field-graph`, `version: 3`; импорт читает 1 / 2 / 3. Виды study / workspace / changes, очередь принятия и компактная история прежние.

Накопительный study содержит обычные nodes / edges / designations / substitutions, совместимый rootId и список rootIds. Дополнительное `accumulation` имеет `version: 1`, `sources`, `decisions`, `aliases` и `camera` (null либо x / y / scale). Все материализованные объекты проверяются по снимкам и решениям; это не произвольные дополнительные поля.

В source сохранены `studyId`, полный `snapshot` независимого исследования, `addedAt`, карты `nodeIds`, `edgeIds`, `designationIds`, `substitutionIds` от исходного ID к отдельному ID копии и начальные `positions`. Карты стабильны при последующих объединениях. `reference` исходного узла — JSON-строка массива `[studyId,nodeId]`; такая кодировка не допускает неоднозначность разделителя в произвольных ID.

Decision содержит `id`, `time`, `status` (confirmed / rejected / pending), `reason`, списки исходных references `left` / `right`, `representativeId` и `evidence`. Отождествление и отказ относятся ко всем представлениям выбранных текущих узлов. Подтверждение требует непустого обоснования; отказ также. Pending остаётся нерешённым. Журнал сохраняет последовательность; imported decision не становится новым выводом из совпадения слова. Проверяется существование представлений, принадлежность представителя паре и непротиворечивость всех сохранённых отказов транзитивным отождествлениям.

Копия каждого ребра содержит собственный ID, перенаправленные from / to, прежние type / role / componentRole / notes и дополнительные атрибуты, `accumulationSourceId` и origin с studyId / studyTitle / edgeId / capturedAt / полным snapshot. Совпадение концов не объединяет рёбра. Узел имеет origins всех исходных представлений; отображаемые текстовые поля взяты из выбранного представителя, остальные версии доступны в origins и source.snapshot. Архивные следы замещений переносятся как в M002.

Alias рабочего словаря содержит id / reference / text / notes / time; это явное обозначение конкретного исходного представления в накоплении. Исходный словарь не изменяется. Материализованный designation сохраняет ID alias и адресует текущий объединённый узел.

Визуальные кандидаты и группы индекса **не входят в JSON как содержательные рёбра**: они вычисляются заново из словарей / явных рабочих обозначений или отдельно технических названий. Кандидаты не участвуют в обходе. Основная camera переносится с результатом; браузерные окна инспекторов и их камеры не являются данными знания.

Полный study-export накопления самодостаточен. Обычный импорт сначала показывает / принимает все метаданные, узлы, рёбра и обозначения атомарно; решения и происхождение накопления сохраняются. Состояние и все строки истории валидируются. Накопление в файле с номером v1/v2 отклоняется. Фрагмент накопления сейчас отклоняется с объяснением: для обмена экспортировать целиком, локальный просмотр доступен в инспекторе. Обычные фрагменты независимых исследований работают как раньше. Прямые содержательные изменения материализации через changes также должны выдержать инварианты, иначе отклоняется весь пакет.
