# Постоянный граф: JSON и хранение M008

`source.responseSha256` — SHA-256 нормализованного JSON-ответа API: `json.dumps(result, ensure_ascii=False, sort_keys=True).encode('utf-8')`, не checksum транспортного сжатого потока. RevisionUrl/номер редакции позволяют получить исходное содержание; fetchedAt фиксирует конкретное получение.

История входных документов сохраняется в `permanent_imports` по SHA-256 документа, в той же SQLite, и возвращается при экспорте как необязательное `importedHistory`. Вход содержит локальную историю источника; она проверяется и архивируется, не заменяя номера текущего журнала и не создавая второго активного графа. Повторный документ не создаёт второй архив. Архивы плоские, без вложенных importedHistory; действует общий предел входного документа 64 МиБ. Это сохранение уже полученной истории, не механизм сопоставления/разделения источников. При повторном экспорте исходная история остаётся доступна в JSON. Рост архива не очищается автоматически; больших коллекций импорта эта проба не измеряла.

Активный экспорт: `{format:"concept-field-permanent",version:1,kind:"graph",state,historyEncoding:"rfc6902-chain-v1",history,exportedAt}`. Это один граф, не workspace независимых studies. В `state` ровно nodes / edges / designations / contextEdges / definitionDrafts / definitionPublications. Пустой граф валиден без rootId. Базовые поля узлов и черновиков/маршрутов сохранены из [M007 v4](data-format-v4.md), но нет accumulation/manual/sources/decisions/nodeIds карт копий.

Новые концепты имеют один UUID, `structure:concept`, `designationOnly:true`, пустой label и внешнее designation `{id,target,text,...}`. Обычное ребро `{id,from,to,role:relation,...}` ссылается на ID концептов. Контекстное `{id,from,to,definitionId}` — на два разных обычных ребра; пара направлена и уникальна. DefinitionId в origins/объекте указывает происхождение создания, а не самостоятельный подграф. Сохранённые drafts/publications адресуют те же IDs и не копируют объекты. IDs всех актуальных концептов/рёбер/контекстов/обозначений/определений глобально различаются; повторы ссылок черновика допустимы как ссылки.

Определение может хранить `source`: name, url, revision, revisionUrl, retrievedAt, license, licenseUrl, attribution, responseSha256, transformation, lemma, senseId, entry, originalText и operatorEdited. Выбранное толкование остаётся черновиком до ручного построения/подтверждения. Если оператор меняет текст, исходный текст/редакция сохраняются и правка отмечается. Публикация и origins сохраняют этот источник.

Сохранение выполняется транзакционно в `permanent_revisions`, отдельном журнале в существующей SQLite. Доступ к старой `revisions` сохраняется только в историческом режиме; это защищённый архив, не часть нового графа. При первом открытии старой базы backup всей SQLite выполняется до CREATE/INSERT новой таблицы, включая WAL; проверяются integrity, SQL digest, SHA-256 копии. Манифест хранится рядом с backup и в init.detail новой истории. Восстановление старой базы выполняют на копии backup через `--legacy`.

Preview и включение используют одну функцию prepare M007 с прямым каноническим набором вместо проекции. `definition_save` сохраняет черновик, `definition_publish` требует confirmed:true и актуальную revision. Повтор не создаёт новых объектов. Чужие подтверждённые ссылки защищены, поэтому удаление их объекта блокирует всю транзакцию. Конструктор изменяет только объекты своего создания; повторно выбранный ID сохраняет исходные поля. Опубликованные списки ссылок — происхождение/защита ручной работы, не границы обхода графа.

Импорт проверяет snapshot и всю history. В чистой базе структура сохраняется точно. В непустой базе добавляются отсутствующие IDs, равные повторы пропускаются, конфликт по ID/составу определения отклоняется целиком. Отсутствие объекта во входе не удаляет старый объект. Для иных изменений используйте конструктор или explicit restore своей локальной версии после резервного экспорта. Imported history переносится в самом документе, но не подменяет локальные номера версий: локальная история фиксирует подтверждённый импорт. Старые concept-field-graph v1–v4 явно отвергаются новым режимом, доступны через --legacy; автоматического переноса нет.
