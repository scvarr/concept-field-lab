# ADR M001: отдельные ручные графы, SQLite и локальный интерфейс

Расширение составных элементов принято в [ADR M002](composition-architecture.md); базовые решения хранения, сервера и обмена сохранены.

Дата: 9 октября 2026. Статус: принято и реализовано.

## Контекст

Нужно ручное рекурсивное построение независимых структур, ежедневная работа через GUI, происхождение, сопоставление по решениям оператора и обмен графами. Установка и запуск должны быть простыми на Windows. Старые исследования механизмов интеллекта не задают архитектуру этого приложения.

## Решение

Python standard library запускает HTTP-сервер на `127.0.0.1`. Статический интерфейс JavaScript / SVG работает локально без CDN, npm-зависимостей и сетевых сервисов. SQLite с WAL и `synchronous=FULL` хранит атомарные сжатые снимки всего пространства, журнал версий и происхождение. Optimistic revision и транзакции предотвращают потерю записи из другой вкладки / процесса. Контекстный менеджер закрывает все соединения, включая Windows file handles.

Каждое исследование имеет собственные UUID-элементы и отношения со свободными типами. Узлы — небольшие карточки содержания; произвольные характеристики можно выразить дополнительными узлами и связями. Циклы разрешены. Соответствия существуют отдельно и не меняют структуры. Объединение создаёт новую структуру с новыми ID и снимками исходников; выбранные соответствия транзитивно задают группы. Не используются общая заранее заданная онтология, генерация, обучение, активация или маршрутизация.

JSON `concept-field-graph` v1 поддерживает пространство, исследование, фрагмент, отчёт diff и пакет кандидатов. Импорт сохраняет ID, обнаруживает повторы / коллизии, хранит чужую историю в архиве и требует review предложений. История экспорта — последовательность JSON Patch; локальные сжатые снимки остаются простым надёжным способом восстановления. Интерфейс отрисовывает ограниченное окружение и страничные списки, а полные графы можно загрузить / рассмотреть пакетами.

## Рассмотренные альтернативы

- Desktop-фреймворк и отдельная сборка: удобная упаковка, но добавляет зависимости / установку; для первого самостоятельного ежедневного инструмента выбран браузерный GUI.
- Только browser localStorage / IndexedDB: простой запуск, но привязка к профилю браузера и менее прозрачные копии / восстановление. Выбрана отдельная SQLite-база.
- Нормализованные SQL-таблицы и журнал событий по объектам: лучше для очень больших пространств / длительной истории; больше миграций и сложности восстановления. На проверенном масштабе достаточно сжатых атомарных снимков и компактного JSON журнала; такая миграция пока не принята.
- Автоматическое слияние по названиям или общей семантической модели: не соответствует независимости исследований и ручному принятию решений.

## Последствия

Для работы нужен Python и браузер; сервис доступен только локально. Пространство читается в память, поэтому это не сервер для миллионов узлов. Проверено 5 000 узлов / 10 000 отношений, массовый импорт, поиск и 20 последующих сохранений; SQLite-файл увеличивается с историей. Нет фоновой очистки, автоматического семантического анализа, multi-user permissions и распределённого редактирования. Изменение смысловой структуры консервативно требует повторного решения её соответствий. Содержательные результаты определяет оператор; синтетические тесты доказывают только работу механики.
