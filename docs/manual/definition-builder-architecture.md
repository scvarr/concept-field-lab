# ADR M007: ручные определения в постоянном полотне

Уточнение после сквозной проверки: `definitionPublications` хранит последний подтверждённый состав определения, включая повторно используемые ID. Он отделён от черновика по ответственности; содержит ссылки и исходный текст, не копирует nodes/edges. Без него удаление ребра владельцем могло бы молча удалить подтверждённое переиспользование другим определением. Ссылочная проверка отклоняет такое изменение. Инспектор использует подтверждённый набор, включая старые выбранные рёбра; черновик не участвует в обходе постоянного графа.

Дата: 13 октября 2026. Статус: принято для ограниченной реализации конструктора; смысловое содержание выбирает оператор.

Контекст: M005 материализует неизменяемые снимки источников и операторские решения. Нельзя записать произвольные новые рёбра прямо в эту проекцию. Нужно вручную ввести первые 3–4 определения, повторно используя выбранные ID, без словарного заполнения графа и разрушительной миграции K001/K002.

Решение: расширить метаданные накопления необязательными `definitionDrafts` и `manual`. Черновик хранится в той же SQLite-истории, но до отдельного подтверждения не входит в nodes/edges полотна. Ручной слой содержит nodes, edges, designations и направленные contextEdges. Проекция добавляет его после исходных представлений; все ссылки и её равенство слоям проверяются транзакционно. Повторное включение заменяет только объекты с definitionId этого определения; удаление используемого другим определением объекта отклоняется целиком.

Новые концепты имеют UUID и пустые label/kind/notes; `designationOnly: true` разрешает пустую техническую подпись. Слово хранится в designation. UI подставляет обозначение только для показа. Часть речи остаётся свойством внешней словарной записи. У исторических узлов не меняются поля или трактовка. Обычные рёбра имеют собственные UUID, контекстные пары ссылаются только на обычные рёбра этого полотна. Существующее ребро используется по явному выбору ID; новое параллельное требует обоснования.

ID исходного исследования и ID его представления на полотне остаются различными согласно M005; оригинальный ID сохраняется в origins. Конструктор использует ID уже существующей копии, не создаёт её заново. Если исходник ещё не включён, оператор отдельно просматривает и подтверждает добавление целого снимка штатным accumulation_add_source. Автоматического отождествления по слову нет. Новые ручные узлы не участвуют в старом механизме классов исходных представлений: для этой проверки достаточно повторного использования их ID. Решение отождествить исходные узлы, от которого ссылки ручного слоя стали бы отсутствующими, безопасно отклоняется; автоматическое переписывание таких ссылок не заявляется.

Маршрут задаётся упорядоченным списком обычных рёбер. Проверяется непрерывность. Только после ручного просмотра оператор подтверждает все пары раньше → позже внутри этого списка. Ветви не анализируются автоматически. Контекст можно добавить, удалить или развернуть вручную; исходная запись подтверждения маршрута остаётся свидетельством. Активация и автоматический выбор маршрута отсутствуют.

Словарный ресурс — пакетный снимок OpenCorpora через pymorphy3-dicts-ru. В репозитории отдельный локальный индекс нормальных форм и признаки, без толкований, предсказаний или узлов графа. Исходное определение вводится оператором. Пакетные инструменты нужны лишь для воспроизведения индекса, не для запуска приложения.

Обмен использует JSON v4 с чтением v1/v2/v3/v4. Метаданные ручного слоя и черновиков входят в существующий кандидат study, обычные материализованные объекты — в прежние кандидаты. Принятие проверяет пакет целиком. Старые файлы/SQLite-снимки не переписываются. Экспорт целого полотна самодостаточен, включая сохранённые черновики и происхождение; частичный экспорт накопления остаётся запрещённым.

Альтернативы: отдельный рисунок без включения не решает задачу; добавление каждого миниграфа как независимого источника создавало бы новые копии повторно выбранных рёбер; превращение словаря в граф создаёт неподтверждённые концепты; общая глобальная миграция ID разрушает совместимость. Выбран небольшой ручной слой поверх существующей проекции, без новых сервисов, БД или renderer.

Последствия: ручные концепты можно находить и повторно использовать по ID, видеть обычное окружение и контекстные пары. Каждое определение обходится в инспекторе отдельно от других ручных определений и исходных снимков; обзор не доказывает допустимость произвольной смешанной цепочки. Черновики ограничены 20 на полотно, каждый — 80 полей / 160 рёбер / 800 контекстных пар / 40 маршрутов, маршрут до 40 рёбер. Это предел данного эксперимента, не инфраструктура массового анализа. Изменённая содержательная версия выбранного узла требует повторного выбора; координаты и pin не мешают переиспользованию. Механизм отождествления ручных узлов с исходными классами и отдельный обмен черновиком между разными полотнами не реализованы.
