# Инструкция оператора

## Запуск в Windows cmd.exe

Нужен установленный Python **3.11 или новее** и современный браузер Edge, Chrome или Firefox. Приложение использует только стандартную библиотеку Python; `pip`, Node.js и сборка интерфейса для работы не нужны. Проверено на Windows 10, Python 3.13.2 и Chrome 154.

Откройте **cmd.exe**:

```bat
cd /d E:\Projects\concept-field-lab
start.cmd
```

`start.cmd` выбирает `py -3`, если доступен Python Launcher, иначе `python`. Браузер откроет `http://127.0.0.1:8765`. Оставьте окно cmd.exe открытым. Для остановки нажмите Ctrl+C. Следующий запуск открывает ту же базу и позволяет продолжить.

Если автоматическое открытие браузера не сработало, введите указанный адрес самостоятельно. Если порт занят:

```bat
start.cmd --port 8766
```

Для запуска без автоматического открытия браузера или с отдельной базой:

```bat
start.cmd --no-browser --db "E:\Projects\concept-field-lab\local-data\other.sqlite3"
```

Можно запустить прямо через Python:

```bat
py -3 -m app.server
```

Путь базы по умолчанию — `local-data\workspace.sqlite3` внутри репозитория, независимо от текущего каталога. База и тестовые артефакты исключены из Git. Сервер доступен только на `127.0.0.1`, внешние сервисы не вызываются. Закрытие вкладки не останавливает сервер; данные уже сохранённых действий остаются в SQLite.

## Построение исследования

1. Нажмите «Новое исследование», введите «камень» и описание. Создаётся собственный корневой узел с новым ID. Новое исследование другого слова, даже одноимённого, получает независимые элементы.
2. В правой форме запишите название, свободный тип / роль, содержание, альтернативные интерпретации и источник. Нажмите «Сохранить элемент». Произношение, грамматику, определение, значение или свойство можно хранить отдельными узлами и пояснять через связи.
3. «Раскрыть узел» создаёт новый элемент и связь от выбранного. Тип отношения задаётся свободным текстом. Новый элемент сразу выбран и может быть раскрыт дальше. Ограничения глубины данных нет.
4. «Связать с существующим» создаёт отношение между имеющимися элементами. В полях начала и конца доступны подсказки с названиями и ID. Выбор по ID различает одноимённые элементы. Разрешены циклы, самоссылки и несколько отношений между одной парой. Пояснение связи может задавать альтернативный смысл отношения.
5. «Отдельный элемент» добавляет несвязанный узел. Все элементы доступны в поиске, включая несвязанные части. Поиск охватывает название, тип, содержание, альтернативы, источник и ID. Ctrl+K переводит фокус в поиск.
6. В карточке узла доступны входящие и исходящие отношения, переходы к соседям, изменение / удаление связи и происхождение после объединений. Удаление элемента удаляет его связи и соответствия, сохраняя прежние версии в истории. Корень удалять нельзя; его можно редактировать. Исследование целиком можно архивировать и вернуть через переключатель «Архив» слева.

Текст формы сохраняется кнопкой. Остальные действия сохраняются автоматически после успешного ответа сервера. Уход с несохранённой формы требует решения о черновике. Строка вверху показывает сохранённую версию или несохранённый текст. В случае конфликта с другой вкладкой обновите страницу и повторите действие; устаревшая запись не перезапишет новую. Перед обновлением скопируйте нужный несохранённый текст.

## Вложенные комбинации и обозначения

1. Создайте обычные элементы «твёрдость», модификаторы и другие нужные концепты. «＋ Комбинация α» создаёт элемент с собственным ID; название и содержательный тип можно оставить пустыми. В карточке отдельно указана **структурная функция**, которая не определяет смысловую категорию.
2. В комбинации «Раскрыть узел» по умолчанию добавляет новый компонент. «Включить существующий компонент» повторно использует имеющийся элемент: выберите его ID. Функция соединения «Включение компонента» направлена **от комбинации к компоненту**. Роль компонента и тип отношения необязательны. «Связать с существующим» позволяет отдельно записать содержательное утверждение.
3. Создайте β как ещё одну комбинацию и включите в неё α. Щелчок по комбинации открывает её непосредственный состав; щелчок по вложенной α открывает её собственные компоненты. Выбор обычного компонента оставляет контекст состава. «Назад», путь над графом и «К исходному узлу» возвращают контекст просмотра. Эти переходы не создают рёбер, не меняют сохранённую версию; после перезагрузки вкладки путь начинается заново.
4. «Показать окружение» переключает к обычному обходу записанных соседних связей. Внешняя связь с α относится к комбинации целиком. Пунктир обозначает включение; связность и общий компонент двух комбинаций не означают общего утверждения. Вложенность и циклы допускаются без заданной максимальной глубины; оператор выбирает переходы.
5. «Обозначение» в карточке связывает слово / выражение с текущим элементом. Это запись внешнего словаря, а не новый семантический узел. Обозначение имеет пояснение и источник, его можно изменить или удалить. Поиск находит α по слову из словаря. Несколько элементов могут иметь одинаковое обозначение; это не подтверждает тождество.

Анонимные комбинации показаны как `α · короткий ID`. Подпись не сохраняется как название; полный ID доступен в карточке. Сопоставление позволяет выбрать любые комбинации вручную. Пустые названия не порождают кандидатов по совпадению имени. Объединение сохраняет включения, словарь и архивные записи исходных замещений вместе с происхождением.

## Подтверждаемое замещение концепта

Создайте отдельно «твёрдый» и выражающую α с компонентами. У концепта нажмите «Заместить комбинацией…», выберите α и «Проверить». Предварительный просмотр показывает все переносимые связи, соответствия, обозначения и изменение корня. Просмотрите объекты, отметьте подтверждение эквивалентности и заполните обоснование. Это ваше семантическое решение; приложение его не устанавливает.

После подтверждения внешние и компонентные ссылки на концепт перенаправляются на α **как целое**, с прежними ID рёбер. Исходный концепт уходит из активного графа, слово становится словарным обозначением α. Полный снимок исходника сохраняется в происхождении и в записи замещения с контекстом до / после. Ранее принятые соответствия требуют повторной проверки. Если замещается корень, α становится корнем.

Приложение отклоняет пустую выражающую комбинацию, включение замещаемого концепта в её состав, возникающую самоссылку и столкновение соответствий. Проблема показана до подтверждения; данные остаются прежними. Например, если вы уже записали связь «твёрдый» → α, сначала решите её значение отдельно: автоматическое превращение в α → α не выполняется.

Разверните запись в разделе «Замещения» и нажмите «Отменить замещение». Исходный концепт, ссылки и словарь восстанавливаются при неизменном затронутом контексте. Если после операции изменены α, её связи, обозначения, корень или соответствия исследования, безопасная локальная отмена отклоняется. Можно вручную решить новые изменения или восстановить полную версию **всего пространства** через историю, предварительно сохранив резервную копию. Архивные записи в объединении служат происхождением и не применяются как локальная отмена новой структуры.

Для знакомства импортируйте `data/fixtures/composition-example.json` через «Обмен и кандидаты», просмотрите и примите пакет. Он содержит X, «твёрдый», две анонимные комбинации с общим «свойство», β → α и обозначение α. На нём можно пройти вложенность и отдельно подтвердить / отменить замещение. Это синтетический пример работы инструмента, его содержание не является подтверждённым толкованием слов.

## Исследование большого графа

Полные данные хранятся независимо от отображения. Граф показывает окружение **выбранного** узла на заданную глубину, не более 180 узлов и 500 связей за один вид. Обход учитывает оба направления. Подпись показывает ограничение. Уменьшайте глубину и переходите к нужному элементу через поиск; это не удаляет скрытые элементы.

Колесо меняет масштаб; перетаскивание фона перемещает вид; щелчок по узлу выбирает его. Перетаскивание узла сохраняет позицию в исследовании. «Вписать» возвращает вид к показанному окружению. «SVG» сохраняет текущий вид как векторную картинку; для полных данных используйте JSON. Списки элементов, связей в карточке, соответствий, кандидатов и истории разбиты на страницы. Внутри комбинации показаны непосредственные компоненты; глубина окружения включается после «Показать окружение». Обзор состава показывает комбинацию и до 14 непосредственных компонентов, включая выбранный компонент; это ограничение отображения, а не данных. Даже при 2 000 компонентах карточка ограничена 60 связями на странице; остальные доступны через поиск и страницы. В сопоставлении поиск выдаёт первые 40 подходящих элементов каждой стороны; уточняйте запрос.

Для больших объёмов используйте импорт графа или пакета предложений, а не ручное создание тысяч узлов. Проверены граф 5 000 узлов / 10 000 отношений и комбинация с 2 000 компонентами; это проверка конкретного масштаба, не обещание неограниченной производительности. Новое смысловое содержание само приложение не генерирует.

## Сопоставление и объединение

Создайте **отдельное** исследование «камня» и раскройте его независимо. Во вкладке «Сопоставление» выберите оба исследования. Поиск и графы позволяют выбрать любые два элемента. Зелёные поля совпадают по значению; жёлтые различаются. Список под графами предлагает одноимённые пары исключительно как кандидатов. Отсутствие названия в списке не мешает выбрать пару вручную.

«Подтвердить соответствие», «Отклонить соответствие» и «Оставить кандидатом» сохраняют решение и обоснование. Они не изменяют сами узлы. В графах зелёный контур показывает узлы с подтверждённым соответствием, красный пунктир — с отклонённым. При наличии обоих решений у узла показывается зелёный контур; полный список сохраняет все решения.

Любое изменение смысловых полей, добавление / удаление узла или изменение отношений в исходной структуре переводит её ранее подтверждённые и отклонённые соответствия в «Не решено». Ранее введённое обоснование остаётся в истории и тексте решения. Это консервативная защита от решений по устаревшему контексту. Перемещение узла и изменение названия исследования не сбрасывают решения.

«Создать объединение» открывает выбор подтверждённых пар. Ничего не выбирается автоматически. Получается **третье исследование**; исходные два не меняются. Выбранные пары отождествляются, остальные элементы остаются отдельными. Несколько пар с общим элементом образуют транзитивную группу; выбирайте их с учётом этого последствия. Корень нового графа соответствует корню первого исследования. В каждой новой карточке есть снимки исходных элементов, их ID, исследования и время; все исходные связи сохраняются, включая параллельные и образовавшиеся циклы. Пояснения, альтернативы и источники объединяемых элементов сохраняются с пометками исходных исследований. Последующее редактирование исходников не меняет уже созданный снимок объединения.

## Обмен JSON и ChatGPT

- «Экспорт исследования» сохраняет все его узлы, отношения, атрибуты, ID и относящуюся к нему историю, включая происхождение импортов. Это формат `concept-field-graph`, версия 2 (импорт v1 сохранён), вид `study`.
- Во вкладке «Обмен и кандидаты» выберите глубину окружения: целое число ≥0 или `all`. «Фрагмент» скачивает JSON, «Копировать JSON фрагмента» переносит его в буфер. `0` — только выбранный узел, `all` — его связная часть, оба направления. Несвязанные части входят в полный экспорт исследования. ID не меняются. Корень фрагмента — выбранный узел; исходный корень указан в `selection.sourceRootId`.
- «Копировать запрос ChatGPT» копирует фрагмент, описание формата и пример ответа `kind: changes`. Вставьте запрос в ChatGPT, получите JSON и перенесите его в поле импорта. Помощь ChatGPT остаётся предложением; истинность содержания проверяет оператор.
- «Экспорт различий» в сопоставлении содержит полные структуры, ручные решения, равные / различающиеся атрибуты и несопоставленные элементы. Названия не используются как доказательство тождества. Сходство отношений по подтверждённым концам и типу отмечается отдельно как структурное сходство.
- В истории «Различия исследования» экспортирует выбранную старую версию против текущей версии активного исследования. Версионный diff содержит `versionChanges`: отдельный пакет кандидатов, который можно передать для анализа / импорта. Сам `diff` — отчёт и не импортируется как решение об отождествлении.

Выберите JSON-файл или вставьте чистый JSON без Markdown ограждений. «Проверить и добавить кандидатов» сначала показывает количество объектов, конфликтов и записей истории, затем добавляет предложения в очередь. Исследования не меняются на этом шаге. Исходные ID сохраняются; точно повторённый документ и уже имеющиеся одинаковые объекты не создают дублей.

В очереди просмотрите текущий и предложенный объект. Выберите отдельные строки или всю очередь и примите / отклоните. При принятии зависимых новых объектов выбирайте вместе метаданные исследования, узлы, отношения, обозначения и записи замещения. Предложение `substitution` переносит сохранённый след операции; само по себе оно не вызывает замещение. Пакет применяется одной транзакцией; ошибочные ссылки или отсутствующие зависимости отклоняют весь пакет. Для редактирования существующего объекта в `changes` передаётся полный `base`; несовпадение с текущим значением показывается как конфликт. Замена конфликта требует отдельной отметки в диалоге. Прежние значения остаются в истории. Коллизия ID с другим исследованием / типом объекта заменой не разрешается: отклоните кандидат и запросите новый ID для нового объекта. Разные предложения одного объекта нельзя принять одновременно.

Импорт не удаляет элементы, отсутствующие в файле. Удаление должно быть явным кандидатом `delete_node` / `delete_edge` / `delete_designation` / `delete_substitution`. Корень защищён. При импорте фрагмента в уже существующее исследование метаданные исходного исследования сохраняются. Утверждения о соответствии из внешнего JSON требуют нового ручного решения; исходный импортированный статус сохранён в архиве происхождения. Уже принятое происхождение узла не стирается предложением изменения. Отклонённые кандидаты и все исходные документы сохраняются в истории и экспорте.

## История и резервное копирование

«История» показывает локальные версии. «Восстановить» возвращает всё пространство к выбранной версии и создаёт новую запись; более поздние записи остаются доступными. История чужого импорта хранится в его архиве JSON, а не подмешивается в нумерацию локальных версий.

«Резервная копия» сохраняет всё пространство, включая архив, решения, очередь кандидатов, исходные импортированные документы и историю. История JSON хранится компактной последовательностью изменений; [описание формата](data-format.md) позволяет восстановить каждую версию. Для переноса на другой компьютер запустите приложение с новой базой и импортируйте копию через очередь. Принятые внешние соответствия потребуется проверить повторно. Для точного переноса **локальных** решений без переинтерпретации можно остановить сервер и скопировать весь каталог `local-data`, включая существующие файлы `-wal` и `-shm`, затем запускать с этим файлом базы. Не копируйте только основной SQLite-файл при работающем сервере.

Ограничение одного запроса импорта — 64 МиБ. Большие наборы можно обменивать отдельными исследованиями, фрагментами или пакетами `changes`. История SQLite хранит сжатые снимки; длительная работа на больших графах увеличивает базу, поэтому сохраняйте резервные копии и следите за свободным местом. Автоматическая очистка истории не выполняется.

## Воспроизводимый пример

`data\fixtures\manual-example.json` содержит две независимые синтетические структуры «камень» и «камня», по 5 узлов / 5 связей, включая циклы. Загрузите файл через импорт и примите все кандидаты; затем проведите собственное сопоставление. Готовых подтверждённых соответствий в файле нет. Это тестовый материал для проверки механики, **не подтверждённые знания и не научный результат**.
