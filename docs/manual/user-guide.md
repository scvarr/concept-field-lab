# Инструкция оператора

## Рабочие области

В компактной верхней панели выберите **«Конструктор определений»** или **«Постоянный граф»**. Отображается только выбранная область на всю ширину: конструктор работает с миниграфом текущего определения, постоянный граф — с общим полотном и окружением. Выбор запоминается в этом браузере. Переключение сохраняет введённый текст и положение миниграфа в открытой странице, но не записывает несохранённый текст в SQLite: перед закрытием/reload используйте «Сохранить черновик».

Из общего графа кнопка **«Использовать ID в черновике»** возвращает в конструктор с выбранным ID. Сведения о проверенной резервной копии прежней SQLite, её скачивание, импорт/экспорт, история и диагностика доступны в **«Данные и история»**. Постоянного уведомления о резервной копии над рабочим пространством нет.

## Словарные обозначения выбранного поля

Двойной щелчок по полю или правый щелчок → **«Обозначения и свойства…»** открывает форму с ID и **«Словарные обозначения · точки входа»**. Можно сразу после создания «деталь» нажать **«Добавить обозначение»** и ввести «гайка». У другого ID, например «птица», можно добавить ту же «гайка»: поиск предложит оба ID, источники и **«Окружение и происхождение»**. Выберите **«Использовать этот ID»** вручную. Это входы в концепт, а не автоматическая синонимичность слов.

В диалоге обозначения нажмите **«Получить значения слова»**, затем **«Связать с этим значением»**: сохранится статья/омоним, номер значения, источник, редакция, исходный текст и условия использования. Доступны ручные поля источника и **«Убрать источник значения»**. Нет сети/толкования — остаётся ввод слова и собственного источника. Получение значения в этом диалоге не заменяет исходное определение миниграфа.

**«Изменить»** правит только выбранное соответствие с сохранением его ID; **«Удалить» → «Удалить соответствие»** удаляет его без удаления концепта, остальных обозначений и рёбер. После удаления всех обозначений поле показывается по ID. Новые поля и их обозначения остаются черновиком до подтверждения включения. Для уже включённого ID правка обозначения сразу сохраняется в общем графе и истории; повторное включение старого определения её не отменяет. Все обозначения видны у поля независимо от определения, создавшего концепт. Экспорт переносит соответствия и источники вместе со структурой и историей.

## Работа непосредственно на полотне

Обычный `start.cmd` открывает одно приложение с двумя переключаемыми областями. В конструкторе отображаются миниграф и короткая строка команд; нижних таблиц полей/рёбер/маршрутов нет. Все подробные формы открываются поверх полотна и прокручиваются внутри своего окна.

```bat
cd /d E:\Projects\concept-field-lab
start.cmd
```

Нужны Python 3.11+ и браузер; npm/pip/сборка не нужны. Адрес `http://127.0.0.1:8765`, SQLite по умолчанию `local-data\workspace.sqlite3`. Отдельная база: `start.cmd --db local-data\my-input.sqlite3 --port 8766`. Остановка Ctrl+C; следующий запуск продолжает сохранённый граф. После обновления интерфейса M011 сохраните открытый черновик, перезапустите `start.cmd` и обновите страницу Ctrl+F5: сервер должен подключить новые файлы меню/форм.

1. Нажмите **«Определение»**, введите название/текст и **«Сохранить определение»**. Либо откройте **«Добавить поле»**, найдите лемму и выберите **«Взять это определение»** у нужного словарного значения. Толкование сохраняет происхождение в черновике и не создаёт концептов автоматически. Без сети доступны локальные формы/cache и собственный текст.
2. Через **«Добавить поле»** или меню свободного места **«Добавить поле / найти ID…»** найдите лемму, обозначение или ID. Существующий ID выбирается явно; **«Создать отдельный концепт»** у словарной формы либо ручной ввод обозначения создаёт новый ID. Одинаковое слово не объединяет узлы. На уже заполненном полотне новое поле ставится в выбранную точку; поля можно перемещать мышью.
3. Правый щелчок по узлу открывает обозначения/происхождение/соединение/удаление из миниграфа. Двойной щелчок открывает форму обозначений. Несколько слов и значения можно привязать одному ID, одно слово — разным IDs. При уже включённом ID отдельная правка обозначения сохраняется сразу; структура графа остаётся прежней.
4. Для обычного ребра выберите у исходного узла **«Соединить отсюда →»**, затем щёлкните конечный узел. На панели появится указание текущего выбора; Escape или «Отменить выбор» отменяет операцию. Если ребро уже существует, форма предложит его ID либо обоснование нового параллельного. Старый ID при reuse сохраняется.
5. Правый щелчок по ребру → **«＋ В выбранный маршрут»** набирает последовательность. Кнопка **«Подтвердить маршрут»** или соответствующая команда меню покажет пары каждого ребра ко всем последующим внутри этой последовательности. Только после подтверждения они записываются в черновик. Каждая ветвь подтверждается отдельно; автоматических пар между ветвями нет.
6. Для ручной пары выберите у исходного обычного ребра **«Контекст отсюда →»**, затем другое обычное ребро. **«Маршруты и контекст»** открывает списки сохранённых маршрутов/пар и выбор по ID; пару можно добавить, удалить или развернуть. Удаление записи маршрута не удаляет его контекст. При перекрытии объектов используйте меню **«Поля и рёбра по ID…»**, чтобы открыть объект или выбрать конец текущей операции.
7. Нажмите **«Включить в граф…»**, просмотрите изменения/IDs, отметьте подтверждение и нажмите **«Включить в граф»**. Это единственное применение структурных изменений черновика к общему графу. Удаление поля/ребра из миниграфа сначала сохраняется только в черновике; чужие подтверждённые ссылки защищены. Повторное включение не создаёт копий и не сбрасывает независимые обозначения.
8. В **«Постоянный граф»** ищите обозначение/ID, перемещайте полотно и инспектируйте объекты через правый/двойной щелчок. Меню узла предлагает окружение и **«Использовать ID в миниграфе»**. **«Редактировать в конструкторе»** открывает черновик происхождения для структурных правок/контекста; они вновь требуют preview и подтверждения. Окружение показывает связность общего графа, а не автоматически выбранный допустимый маршрут.

Кнопка **«Действия ▾»** открывает то же меню для выбранного объекта; Shift+F10 / клавиша меню — для сфокусированного SVG-объекта. Tab перемещает фокус, стрелки — внутри меню, Escape закрывает меню/отменяет текущий выбор. Отдельные формы сохраняют доступ к операциям без правой кнопки мыши. Список сохранённых определений и **«Новое»** переключают черновики; приложение продолжает ручную работу, без определения смысла по контексту или активации.

Операции с полями/рёбрами/контекстом сохраняют черновик в SQLite. Текст определения сохраните в своей форме до закрытия страницы. Изменения текущего текстового черновика остаются в памяти открытой страницы при закрытии формы и переключении вида, но не после reload без сохранения. Источники и IDs доступны в формах. Старый редактор исследований для этого не нужен.

## Данные и история

Кнопка **«Данные и история»** открывает служебный диалог, а не третью рабочую область. Экспорт/резервная копия JSON включает весь постоянный граф, черновики, происхождение, локальную историю и архив полученной истории импорта. Импорт: выберите этот JSON, просмотрите изменения, подтвердите. Он добавляет отсутствующие IDs, пропускает точные повторы и целиком отклоняет конфликты. Совпадение текста не объединяет концепты. Входные отсутствующие объекты не удаляют существующие; изменение уже введённого выполняйте в конструкторе. История позволяет явно восстановить весь граф из собственной версии, сохраняя более поздние строки журнала. Диагностика показывает режим, путь базы и резервного сохранения.

[Формат постоянного графа](data-format-permanent.md) — `concept-field-permanent` v1. Старые `concept-field-graph` v1–v4 новым режимом не импортируются: чтобы не перенести исторические исследования автоматически, открывайте их отдельно.

## Безопасное открытие старой SQLite

При первом обычном запуске со старой базой приложение сначала делает SQLite backup **всей** базы (включая WAL), проверяет integrity_check и совпадение SQL-содержимого, сохраняет SHA-256 и JSON-манифест в `local-data\backups\`. Только после успеха создаётся пустой постоянный граф в новой таблице; прежние данные `revisions` не изменяются. Если резервная запись/проверка невозможна, переход прекращается с ошибкой, новая таблица не создаётся. Исторические K001/K002/K003/полотно не появляются в активном графе.

В «Данные и история» находятся сообщение о сохранении прежней базы и путь/проверки копии. Кнопка «Скачать проверенную старую SQLite» выдаёт отдельный backup. Сохраните его вместе с JSON-манифестом; проверка файла в PowerShell: `Get-FileHash -Algorithm SHA256 <путь-к-копии>` и сравнение sha256 с манифестом. После первого перехода новые открытия продолжают постоянный граф и не создают повторный backup.

Для просмотра/восстановления исторических данных сделайте **отдельную рабочую копию** резервной SQLite, оставив оригинальный backup нетронутым:

```powershell
Copy-Item -LiteralPath 'local-data/backups/<имя-backup>.sqlite3' -Destination 'local-data/legacy-recovered.sqlite3'
python -m app.server --legacy --db local-data/legacy-recovered.sqlite3 --port 8766
```

Явный `--legacy` открывает прежний редактор. [Историческая инструкция](legacy-user-guide.md) описывает его исследования, накопление и обмен. При отсутствии резервного перехода старые Git-артефакты можно импортировать именно туда; из него они не переходят в новый граф. Содержимое backup не редактируйте напрямую: это проверяемый исходный снимок.

## Границы

Сохраняются пределы M007: 20 черновиков, каждый до 80 полей / 160 обычных рёбер / 800 контекстных пар / 40 маршрутов по 40 рёбер. Основной граф показывает до 1000 узлов / 3000 рёбер; поиск охватывает полные данные. Служебный список последних локальных версий ограничен 80 строками, полная история есть в экспорте. Вход JSON до 64 МиБ. История растёт; автоматическая очистка не выполняется.
