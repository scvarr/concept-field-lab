# Инструкция оператора

## Новый рабочий процесс M008

Обычный запуск `start.cmd` открывает один постоянный граф. Отдельные исследования, добавление источников, сопоставление и объединение не нужны. Конструктор слева и постоянный граф справа работают в одном приложении; кнопки «К конструктору» / «К постоянному графу» переводят фокус. На узком экране области расположены последовательно.

```bat
cd /d E:\Projects\concept-field-lab
start.cmd
```

Нужны Python 3.11+ и браузер, Node.js/pip/сборка не нужны. Адрес `http://127.0.0.1:8765`, база по умолчанию `local-data\workspace.sqlite3`. Для отдельной базы: `start.cmd --db local-data\my-input.sqlite3 --port 8766`. Остановка Ctrl+C; следующий запуск продолжает тот же граф.

1. В поиске конструктора введите нормальную форму, например **«гайка»**. Локальные формы и граммемы OpenCorpora доступны без интернета. Для точной найденной леммы приложение показывает толкования русского Викисловаря; у других найденных вариантов нажмите «Показать толкования»: омоним/номер значения, текст, редакцию, источник и лицензию. «Обновить толкования» запрашивает сеть; при сбое доступны ранее сохранённые значения. Если статьи/сети/кэша нет, введите своё определение в текстовое поле.
2. Нажмите **«Взять это определение»** у нужного значения. Это сохраняет текст и происхождение в черновике и не создаёт концептов. Для своего текста задайте название и определение, нажмите «Сохранить черновик». «Новое определение» сохраняет предыдущий черновик и открывает пустой. Источник выбранного толкования виден под текстом; изменение текста отмечается, оригинал сохраняется.
3. Найдите нужный концепт по обозначению или полному ID. Выдача показывает существующие IDs общего графа, количество связей, происхождение и подтверждённые определения, где он используется. Одноимённые концепты остаются разными, выбирайте по окружению. **«Использовать этот ID»** выбирает тот же объект. **«Создать отдельный концепт»** у словарной формы либо «Создать новый концепт» с вашим внешним обозначением создаёт поле черновика. Грамматический класс слова не назначает категории концепту.
4. Выберите поля «От» / «К» и нажмите **«Соединить →»**, повторите для ветвей. При уже существующем соединении явно выберите ID обычного ребра. Оно не копируется; новое параллельное требует обоснования. Вписывание миниграфа и переключатель ID меняют только показ. Поля можно перемещать и убирать.
5. Наберите последовательность кнопками **«＋ В маршрут»**. «Просмотреть и подтвердить маршрут» покажет пары каждого ребра ко всем следующим только в этой последовательности. После вашего подтверждения пары сохранятся в черновике. Отдельно подтвердите другую ветвь: произвольных связей между ветвями нет. Контекстные пары можно вручную добавить, удалить или развернуть. Удаление записи маршрута не пересоздаёт удалённый контекст.
6. Нажмите **«Просмотреть изменения постоянного графа»**, проверьте IDs, отметьте подтверждение и нажмите **«Включить в граф»**. IDs переходят в постоянный граф без копий. Повторное включение не добавляет дублей. Изменение объекта, от которого зависит другое подтверждённое определение, может быть отклонено; сначала пересмотрите его использование.
7. Справа ищите концепт по обозначению/ID, перейдите к его позиции, откройте окружение или карточку ребра. Окружение обходит общий граф независимо от истории определений. Связность не доказывает допустимость маршрута; контекст между рёбрами инспектируется отдельно. **«Использовать ID в черновике»** берёт выбранный концепт в текущий миниграф.
8. Для следующего определения выберите новое словарное значение или «Новое определение»; используйте найденные прежние IDs концептов и рёбер. Список сохранённых определений открывает любой черновик для правки и повторного включения.

Операции конструктора сохраняются в SQLite. Изменения текстовой формы сохраните отдельной кнопкой; несохранённый текст после reload не восстанавливается. Смысл, поля и маршруты выбирает оператор, автоматической декомпозиции нет.

## Данные и история

Кнопка **«Данные и история»** открывает служебный диалог, а не третью рабочую область. Экспорт/резервная копия JSON включает весь постоянный граф, черновики, происхождение, локальную историю и архив полученной истории импорта. Импорт: выберите этот JSON, просмотрите изменения, подтвердите. Он добавляет отсутствующие IDs, пропускает точные повторы и целиком отклоняет конфликты. Совпадение текста не объединяет концепты. Входные отсутствующие объекты не удаляют существующие; изменение уже введённого выполняйте в конструкторе. История позволяет явно восстановить весь граф из собственной версии, сохраняя более поздние строки журнала. Диагностика показывает режим, путь базы и резервного сохранения.

[Формат постоянного графа](data-format-permanent.md) — `concept-field-permanent` v1. Старые `concept-field-graph` v1–v4 новым режимом не импортируются: чтобы не перенести исторические исследования автоматически, открывайте их отдельно.

## Безопасное открытие старой SQLite

При первом обычном запуске со старой базой приложение сначала делает SQLite backup **всей** базы (включая WAL), проверяет integrity_check и совпадение SQL-содержимого, сохраняет SHA-256 и JSON-манифест в `local-data\backups\`. Только после успеха создаётся пустой постоянный граф в новой таблице; прежние данные `revisions` не изменяются. Если резервная запись/проверка невозможна, переход прекращается с ошибкой, новая таблица не создаётся. Исторические K001/K002/K003/полотно не появляются в активном графе.

Уведомление и «Данные и история» показывают путь/проверки копии. Кнопка «Скачать проверенную старую SQLite» выдаёт отдельный backup. Сохраните его вместе с JSON-манифестом; проверка файла в PowerShell: `Get-FileHash -Algorithm SHA256 <путь-к-копии>` и сравнение sha256 с манифестом. После первого перехода новые открытия продолжают постоянный граф и не создают повторный backup.

Для просмотра/восстановления исторических данных сделайте **отдельную рабочую копию** резервной SQLite, оставив оригинальный backup нетронутым:

```powershell
Copy-Item -LiteralPath 'local-data/backups/<имя-backup>.sqlite3' -Destination 'local-data/legacy-recovered.sqlite3'
python -m app.server --legacy --db local-data/legacy-recovered.sqlite3 --port 8766
```

Явный `--legacy` открывает прежний редактор. [Историческая инструкция](legacy-user-guide.md) описывает его исследования, накопление и обмен. При отсутствии резервного перехода старые Git-артефакты можно импортировать именно туда; из него они не переходят в новый граф. Содержимое backup не редактируйте напрямую: это проверяемый исходный снимок.

## Границы

Сохраняются пределы M007: 20 черновиков, каждый до 80 полей / 160 обычных рёбер / 800 контекстных пар / 40 маршрутов по 40 рёбер. Основной граф показывает до 1000 узлов / 3000 рёбер; поиск охватывает полные данные. Служебный список последних локальных версий ограничен 80 строками, полная история есть в экспорте. Вход JSON до 64 МиБ. История растёт; автоматическая очистка не выполняется.

Толкования — внешний источник под CC BY-SA 4.0; [происхождение и условия](../../data/dictionary/NOTICE.md). Локальный индекс OpenCorpora остаётся фиксированным снимком 2022 года. Ошибки сети или изменение разметки Викисловаря могут оставить только кэш/ручной текст. Не реализованы активация, сцены, автоматический выбор смысла/маршрута или новая онтология.
