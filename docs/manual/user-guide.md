# Инструкция оператора

## Разбор через текст M021

Нажмите **«Новая фраза»** и введите текст. Выбирать сцену не требуется: разбор идёт в текущей динамической сцене. При пустом старте она создаётся автоматически. Сохранённую конструкцию можно выбрать в дополнительном разделе; это не автоматическая классификация текста.

Выделите слово или фрагмент в основном поле и откройте меню правой кнопкой либо кнопкой **«Действия с фрагментом»**. Для клавиатуры раскройте **«Редактировать исходный текст»**, выделите диапазон обычными клавишами и нажмите **Shift+F10**. Само выделение не меняет текст. На сенсорном экране предусмотрены выделение и отдельная кнопка; физический сенсорный аппарат пока не проверен.

В меню можно привязать фрагмент к уже существующему локальному элементу; найти постоянный концепт или прежний сценический экземпляр; создать независимый экземпляр; создать элемент вместе с содержательной привязкой; изменить или убрать сопоставление. В короткой форме явно выберите существующую позицию/концепт или создание нового. Alias нового концепта — необязательная рабочая подпись без словарного обозначения. Checkbox подтверждает выбранное вами направление обычного отношения **элемент → содержание**. Новые постоянные объекты проходят preview M018; подходящее существующее ребро выбирается отдельно. Иное направление или сложная структура задаются через граф и подробные операции.

После применения фрагмент отмечается прямо в тексте, а соответствующие локальные узлы появляются на GraphView. Нажмите разметку для меню привязок. Подписи вроде «Объект 1» устойчивы в текущей сессии; они не заменяют постоянные ID и не устанавливают тождество по тексту. При повторном упоминании в поиске выбирайте **«тот же объект текущей сцены»** только если вы действительно подтверждаете идентичность. Использование одного концепта для нового независимого экземпляра — отдельное действие.

Чтобы соединить элементы, откройте меню начального узла → **«Соединить…»**, затем выберите конечный узел на полотне. То же действие доступно в небольшом инспекторе выбранного узла; клавиатура — Shift+F10/Enter на узлах. Выберите существующее обычное ребро либо создайте недостающее через M018. Порядок слов не создаёт смысловых отношений. Доступное контекстное продолжение показано отдельно и выполняется только вашей командой. **«Постоянное окружение»** открывает соответствующий участок общего графа; вкладка **«Динамический»** возвращает текущий разбор.

Снятие привязки оставляет локальный элемент, убирая только текстовое сопоставление. Изменение исходного текста очищает все диапазоны; привяжите фрагменты заново. Несопоставленный текст, пробелы обязательной структуры и содержательные требования остаются видимыми. Перед завершением проверьте и подтвердите содержание. Для определения оставьте **«Утверждение / состояние»**; для события явно выберите **«Событие»**. Это ваше решение, а не распознавание системой.

После завершения результат уже находится в динамической сцене. При желании нажмите **«Включить в сцену знаний»**, выберите существующую сцену или создайте новую с названием. Например, «Словарь» — обычная сцена знаний; следующее определение можно включить туда же. Повторное включение этого разбора в ту же сцену возвращает прежнюю запись. Текст/привязки/происхождение сохраняются; конкретные экземпляры разных сцен независимы, общими остаются постоянные концепты и отношения. Сохранение в знания не выбирает контекст и не активирует всё содержимое сцены.

История/черновики, управление сессией и подробные ID свёрнуты в отдельные разделы. Новая динамическая сессия не удаляет постоянный граф или знания. Управление данными, preview удаления, reset, экспорт/импорт и восстановление M020 по-прежнему доступны. При удалении исходного разбора preview перечисляет зависящие копии знаний: отмените операцию, если их нужно сохранить. Подробнее о границах — [отчёт M021](composition-verification.md#m021-интерактивный-текст-и-сцены-знаний-16-октября-2026).

## Основной инструмент M020

Для нового исследования используйте новый отдельный путь, без импорта демонстрации:

```powershell
python -m app.server --db test-output/my-operator-research/workspace.sqlite3 --port 8770 --no-browser
```

Откройте `http://127.0.0.1:8770`. Сохранённый результат проверки можно импортировать из [export.json](evidence/operator/export.json), но для работы он не нужен. Путь пользовательской SQLite для экспериментов не используйте. Прежний сервер/открытые пользовательские базы не требуют остановки.

В основной навигации три уровня: **Динамический** (ввод, текущая сцена, экземпляры, контекст, активации), **Знания** (накопленные сцены, связи, конструкции и применения), **Постоянный** (единый граф и M018). Построение идёт от постоянных ID к конкретным применениям; поиск — от текущей сцены к знаниям и графу. Смысл задаёт оператор. Конструктор определений в обычном процессе не нужен и не загружается.

**Начать и продолжить.** В динамическом уровне можно создать/открыть сцену либо начать новую фразу; при первом завершении без сцены создаётся «Ручные мысли». Новая фраза закрывает прежнее полотно, сохраняя запись в своей коллекции. Раздельные списки открывают незавершённый черновик для продолжения либо завершённую мысль для просмотра. «Закрыть разбор / очистить полотно» не удаляет данные и не подставляет другой старый разбор. «Новый разбор на основе этого» создаёт отдельное исправление с происхождением; прежнее событие остаётся до явного удаления. Шаблоны находятся в своей библиотеке, не являются мыслями или концептами.

**Построить.** Выделите фрагмент, создайте концепт через M018 или найдите существующий ID. Безымянному концепту можно дать рабочий alias, не добавляя слово в словарь. Новый концепт сразу предлагается для локального заполнения. «Связь экземпляров» выбирает локальные концы и предлагает существующее постоянное ребро; если его нет, создание через M018 после preview сразу возвращает связь в разбор без повторного выбора концов. Существующее обычное использование активно без seed. Контекст создаётся между ID обычных рёбер; локальное разрешение и команда продолжения остаются отдельными решениями, гипотеза не создаёт знания. Все прежние режимы GraphView/маркеры сохранены.

**Выбрать тождество.** В поиске по текущей сцене есть разные действия: использовать **концепт для нового экземпляра** и **подтвердить тот же объект текущей сцены**. Во втором случае показывается точный ID, значение берётся у выбранного объекта, новая мысль адресует его же. Например, после «Винт упал на пол» для «Затем винт покатился» выберите прежний объект винта, а процесс качения создайте независимо. У двух мыслей совпадёт ID предмета, но не процессов. В форме позиции также можно выбрать существующий экземпляр той же сцены/концепта либо новый. Общая подпись/концепт не выполняет объединение автоматически. Значение связанного объекта нельзя произвольно переписать или перенести в другую сцену.

**Проверить обе полноты.** После заполнения обязательных позиций шаблон может быть полным, а содержание — ещё нет. В форме элемента отметьте «Значение требует содержательной связи» и выберите необходимые локальные обычные отношения. Для позиции Объект это может быть `Объект → Винт`; программа сама не назначает такое значение узлу. Сохранённый шаблон помнит необходимость привязки. При новом вводе исключённое ребро её не заменяет: для гайки явно выберите связь к Гайке, для короткого «Винт упал» включите Винт и отношение к нему. XXX при этом можно оставить исключённым.

Панель «Две проверки полноты» находится перед списком элементов. Она показывает обязательную структуру, неподтверждённые содержательные привязки и несопоставленные диапазоны текста. Чтобы сопоставить фрагмент, выделите его в исходной фразе и выберите включённый ID кнопкой «Сопоставить выделенный фрагмент». В проверке видны также исключённые отношения: необязательность в шаблоне не означает ненужность для конкретного содержания. Затем отдельно подтвердите необходимые связи. Только после этого завершайте мысль. Содержательная правка снимает подтверждение; координаты/выделение — нет. Неполный «Человек ударил» на трёхпозиционном шаблоне не завершится и не сменит шаблон. Старое завершение M019 без отдельной проверки явно обозначается как прежняя запись, не объявляется проверенным задним числом.

В «Знаниях» можно открыть конструкции и прежние применения или начать мысль в выбранной сцене тем же редактором. Там же доступны старые явные операции сцен/рабочих извлечений для проверки накопленных данных. Тип `knowledge` не вычисляет степень абстрактности и не устанавливает смысл. Контекст разговора выбирается из динамического уровня явно по сцене знаний; произвольный текст не разбирается системой.

**Удалить или очистить.** Действия различаются по объёму:

| Действие | Что меняется |
|---|---|
| Закрыть разбор / очистить его полотно | Только текущая открытая запись; сохранённые данные остаются в коллекциях. |
| Скрыть полотно / показать сохранённый граф | Только представление постоянного графа. Возврат сбрасывает фильтры/камеру, не удаляет узлы. |
| Удалить этот разбор | Черновик либо завершённая запись; для завершённой будут перечислены вход и зависимые применения/извлечения. |
| Удалить шаблон | Запись библиотеки; прежние применения сохраняют снимок версии/контракта. |
| Удалить сцену или её вход | Выбранная сцена/вход с явно обработанными объектами, ссылками, снятиями, разборами и копиями. |
| Удалить группу | Явно выбранные постоянные узлы, рёбра, контекст, обозначения и перечисленные зависимые записи. |
| Полный сброс исследования | Всё текущее рабочее состояние: граф, сцены, разборы, шаблоны, гипотезы и определения; история остаётся. |

«Управление данными» открывает общий список с поиском и выбором записей. Действия удаления есть также рядом с текущим разбором, шаблоном, сценой, входом и в формах M018. На постоянном уровне доступен выбор группы. Исторические определения открываются там для просмотра/удаления; их удаление сохраняет происхождение оставшихся графовых объектов снимком, не удаляет сами структуры.

Сначала получите preview: точные ID, количества, зависимости между уровнями и изменения происхождения. Если есть блокирующие записи, выберите нужные из списка (либо все перечисленные) и **пересчитайте preview**. Ничего не удаляется от одного предложения системы. Неиспользуемые экземпляры удаляемой мысли можно включить дополнительно; по умолчанию они сохраняются. Общий объект другой мысли не предлагается как осиротевший. До окончательной записи доступен экспорт. После просмотра требуется отдельный checkbox и подтверждение. Отмена, stale revision, изменившийся план или неполный состав оставляют сохранённое состояние целым. UI сразу показывает фактический результат, без старого полотна.

«История и обмен» сохраняет экспорт/import, диагностику и restore. Сброс/удаление не стирает журнал или Git-свидетельства: можно восстановить полный прежний снимок, включая сцены и постоянный граф. После reset можно сразу создать новую фразу/узел без ручной работы с SQLite. Это очистка текущего исследования, не физическое уничтожение истории базы.

Перезапуск сохраняет серверные черновики/сопоставления, ID и решения. Текст сохраняется после 600 мс покоя; кнопка сохранения фиксирует его сразу. При конфликте вкладок локальная страховочная копия остаётся для явного восстановления после обновления. Редактирование исходного текста очищает прежние смещения и явно показывает несопоставленное; смысловая интерпретация не выполняется. Объёмы и ограничения — [ADR M020](scenes-mvp.md#adr-m020-три-уровня-идентичность-и-управление-состоянием-15-октября-2026). Следующие разделы описывают прежние checkpoints и не требуют возвращаться к конструктору определений.

## Ручной разбор фразы M019

Запустите приложение с **новым отдельным путём**; без генератора и без изменения пользовательской SQLite:

```powershell
python -m app.server --db test-output/manual-thoughts/workspace.sqlite3 --port 8769 --no-browser
```

Откройте `http://127.0.0.1:8769`. Основная вкладка «Разбор фразы» открывается по умолчанию; прежний выбор вкладки браузер запоминает. Не указывайте путь существующей пользовательской базы для проверки. Можно импортировать [экспорт реального браузерного разбора](evidence/thoughts/export.json) через «Данные и история» либо начать на пустом графе. Импорт — добавление по ID с preview, конфликт не заменяется автоматически.

1. «Новая фраза» → введите текст и выберите прежнюю конструкцию либо ручное построение. Выделите мышью нужный фрагмент исходного текста. Он остаётся виден рядом с полотном.
2. «Новый концепт…» открывает M018: внешнее обозначение необязательно. После preview и подтверждения задайте **локальное значение**, рабочий alias при необходимости и обязательность позиции. Alias «Объект»/«Процесс» не создаёт словарного слова и не задаёт смысл. Для существующего ID используйте «Найти / использовать…»: источники идут от текущей сцены к накопленным конкретным сценам, сценам знаний и постоянному графу. Можно искать ID/alias/обозначение/окружение; очистка запроса показывает безымянные концепты. У каждого видны ID, соседние отношения и прежние употребления. Выбор всегда создаёт отдельный локальный экземпляр, не объединяет его с прежним предметом.
3. «Связь экземпляров…» → выберите локальные концы. Форма предлагает подходящие существующие обычные рёбра по точным ID концов. Если их нет, «Создать недостающее ребро M018…», подтвердите preview, затем повторно выберите связь. Она сразу непосредственно активна; seed не требуется. Повтор той же локальной связи запрещён. Новое параллельное постоянное ребро требует обоснования M018.
4. «Контекстное разрешение…» создаёт направленную пару между **ID обычных рёбер** через M018. «Использовать разрешение…» выбирает её локальные источник и продолжение. Можно также включить режим «Контекст →» на полотне и нажать два маркера рёбер. Наличие пары не превращает продолжение в факт. Чтобы исследовать доступность, откройте использование целевого ребра и снимите его непосредственное включение; оба локальных конца должны оставаться заполненными. Доступное продолжение отображается отдельно и оранжевым. Только явная команда делает его активным по контексту, с трассой.
5. Щелчок по списку или двойной щелчок по узлу открывает значение/включение/обязательность и правку постоянного концепта M018. Для рёбер/разрешений действуют аналогичные списки. Точное направление и структура остаются решениями оператора; узлы можно перетаскивать. Необязательный элемент исключайте вместе с его использованием, а не заполняйте вымышленным значением.
6. «Сохранить конструкцию как шаблон…» → выберите подмножество структуры и название. Обязательность задаётся в формах элементов, обычных использований и контекстных разрешений. Ребро требует выбранные концы, разрешение — выбранные обычные рёбра. Новая конструкция не создаёт α. В библиотеке доступны поиск, структура отношений и прежние применения; одинаковые узлы не означают одинаковые мысли.
7. При повторном применении значения пусты, необязательное исключено. Заполните обязательные позиции; включите нужное необязательное и повторно используйте постоянные ID. «Завершить мысль в сцене» сохраняет заполнение как событие выбранной сцены; при отсутствии сцены создаёт разговор «Ручные мысли». Неполная обязательная структура даёт отказ, черновик остаётся. Выбранная трёхкомпонентная конструкция не заменяется двухкомпонентной.
8. Чтобы пересмотреть состав выбранного шаблона, нажмите **«Начать явное уточнение структуры»**; решение и старая ссылка останутся в истории. Затем сохраните новую конструкцию или новую версию прежней. Старые применения не меняются. Завершённая мысль доступна для просмотра; для нового применения используйте библиотеку.

Для «Винт упал на пол» можно создать безымянные Объект/Процесс/XXX, содержательные Винт/Падение/Пол, обычные связи и явное разрешение Объект → Винт ⇒ Процесс → Падение. Пометьте Объект, Процесс, их связь и связь Процесс → Падение обязательными, продолжение через XXX — необязательным. Конец обязательного ребра также нужно заполнить, даже если у самой позиции не стоит флаг обязательности. Значение XXX инструмент не назначает. «Винт упал» завершится тем же шаблоном без XXX. Для «Гайка упала на землю» повторно выберите Объект, Процесс, Падение, XXX и их отношения; создайте только недостающие Гайку/Землю и отношения к ним. Прежняя связь к Винту не заменяется связью к Гайке автоматически.

Для «Человек ударил человека» можно выбрать другую структуру с тремя обязательными позициями и двумя **разными локальными экземплярами одного ID Человек**. Значения и активации не разделяются между экземплярами. «Человек ударил» остаётся неполным при незаполненной третьей позиции. Инструмент не определяет, что означает фраза или какой шаблон ей подходит.

Текст и выделение автоматически сохраняются после 600 мс покоя, кнопка «Сохранить черновик» немедленно фиксирует ввод. Изменение исходного текста очищает прежние текстовые соответствия, чтобы не хранить неверные смещения; локальные значения остаются для пересмотра оператором. Рестарт продолжает серверный черновик. При конфликте/недоступном сервере локальная страховочная копия остаётся в данном браузере; «Обновить» получает текущую revision, затем «Восстановить в редактор для проверки» позволяет явно вернуть собственный ввод и сохранить его после просмотра. История сервера, restore и export/import сохраняют граф, alias, шаблоны, заполнения, фрагменты и происхождение. Несохранённый ввод другого браузера страховочная копия не восстанавливает.

Раздел гипотез фиксирует кандидата, основания и решение. Кандидат не добавляет контекст. Принятие требует отдельного создания разрешения через M018; отклонение остаётся в журнале. Математического генератора нет. Фактические пределы и нерешённые вопросы — [ADR M019](scenes-mvp.md#adr-m019-ручной-разбор-и-операторские-конструкции-15-октября-2026).


## Сцены и рабочая область MVP

Для знакомства используйте **новую отдельную базу**. Эти команды не открывают `local-data/workspace.sqlite3`; генератор откажется работать с уже существующим файлом. Из корня проекта в PowerShell:

```powershell
python -m scripts.scenes_fixture --review --db test-output/scenes-review-demo/workspace.sqlite3
python -m app.server --db test-output/scenes-review-demo/workspace.sqlite3 --port 8768 --no-browser
```

Откройте `http://127.0.0.1:8768` и вкладку «Сцены и рабочая область». Генератор с `--review` создаёт A–D и исправления review: независимые знания «Гайка — деталь» / «Винт — деталь» с общим содержательным ID «Деталь», «Физика» / «Химия», три сообщения о винте, две независимые рабочие копии и историю смены темы. Без `--review` сохранена историческая фикстура 78002f2 с одними позициями шаблона; она не доказывает содержательную идентичность. Это синтетический операторский ввод, не результат понимания текста. Для полностью ручного прохода запустите генератор с `--review --scaffold-only`: останется только каркас. Для пустого приложения задайте новый путь базы серверу, не вызывая генератор.

1. Через прежние конструктор/редактор создайте каркас: концепты «Объект», «Категория», «Место»; возможные отношения `classification` («является»), `location` («лежит на»), `fall` («упал на»). Последние два идут от «Объекта» к «Месту», поэтому при создании параллельного ребра укажите различие состояния/события. Фикстура делает эти же явные операции через API. Для исправленной модели добавьте содержательные концепты «Гайка», «Деталь», «Винт» как отдельные стабильные ID. Классификации между ними не добавляйте: утверждения «Гайка — деталь» / «Винт — деталь» будут заполнениями сцен. В каркасе нет конкретных винта №1, стола и пола.
2. «Создать сцену» → «Накопленное знание» → «Гайка — деталь». «Добавить объект»: «Гайка» с позицией шаблона «Объект» и содержательным концептом «Гайка»; «Деталь» с позицией «Категория» и содержательным концептом «Деталь». В другой независимой сцене «Винт — деталь» создайте отдельные локальные объекты, выбрав для детали **тот же ID** содержательного концепта; подпись может отличаться. Обозначения и общий `category` сами идентичности не задают. В назначении входа оставьте «Сведения / текущее состояние», укажите текст и заполните `classification` этими объектами. «Сохранить вход». Можно добавить несколько заполнений в один вход, не создавая отдельную сцену на каждое утверждение.
3. Создайте сцену знания «Физика», свяжите её с «Гайка — деталь». Создайте сцену «Разговор» назначения «Разговор»; она станет текущей. Назначение входа → «Выбор контекста по обозначению сцены», текст → «Физика», сохранить. Появятся накопленная ссылка, вход истории и действующий контекст. Для фразы «Обсуждаем физику» выберите сцену «Физика» в отдельном поле «Сцена действующего контекста». Затем сохраните «Теперь обсуждаем химию», явно выбрав заранее созданную сцену «Химия». Последний вход сменит тему; Физика/её знания останутся доступными вне действующего контекста. Произвольный русский текст без ручного выбора темы не разбирается. Извлечений от смены темы не появляется. Неизвестное или неоднозначное обозначение отклоняется.
4. В разговоре создайте один объект «Винт №1» с позицией «Объект» и содержательным концептом «Винт» и два объекта «Стол», «Пол» с концептом «Место». В первом входе выберите состояние, текст «Винт лежит на столе», отношение `location`, винт → стол, слот `положение`.
5. Во втором входе выберите событие, текст «Винт упал на пол», `fall`, тот же ID винта → пол; явно отметьте снятие прежнего положения. После сохранения текущего положения нет. В третьем входе: состояние, «Винт лежит на полу», `location`, прежний ID винта → пол, слот `положение`. Текущая проекция покажет пол, история — все три входа и событие. Смысл текста не меняет заданные оператором заполнения.
6. Создайте рабочую область. Источник → «Гайка — деталь», отметьте нужное утверждение, «Извлечь независимую копию». Раскройте происхождение и состав. «Задать seed вручную» меняет только эту копию. Повторное извлечение создаёт другую копию в `inactive`.
7. Для проверки шага добавьте в разговор явно структурированное «Винт — деталь» через `classification`, выбрав прежний содержательный ID «Деталь» для нового объекта категории. В каркасе задайте направленную контекстную пару `classification → location` (фикстура её уже содержит). В одном извлечении разговора выберите классификацию и текущее положение **того же винта**. Seed классификации создаёт кнопку разрешённого шага к положению. Нажатие устанавливает `context` и сохраняет трассу. Без пары, в обратном направлении, для другого винта либо между двумя извлечениями шаг не предлагается и сервером не принимается. Общий содержательный ID не объединяет независимые сцены: сопоставление между ними пока не реализовано.

«Просмотр сцены» меняет только просмотр. «Сделать текущим разговором» меняет выбранную разговорную сцену; справа показываются её области. «Обновить с сервера» восстанавливает согласованное состояние после конфликта вкладок; незаписанные поля при этом сбрасываются. Для исправления/отката доступно полное восстановление версии через «Данные и история»: оно восстанавливает **каркас, все сцены и области вместе**, не одну реплику. Позднейшая история сохраняется. Экспорт со сценами — v3; прежний граф без сцен сохраняет v2. Конфликтующие ID сцен при импорте не сливаются автоматически.

Источники извлечения сгруппированы по действующему контексту и прочей накопленной доступности. Источник вне текущей темы можно явно выбрать; это не меняет тему разговора. Смена темы не сбрасывает старые копии и не переосмысливает их seed/context. Рабочая область не синхронизируется с изменениями источника. В ней виден номер версии извлечения; новое извлечение получает новые ID. Ограничения локального механизма и нерешённые вопросы — [модель MVP](scenes-mvp.md). Обычный `start.cmd` по-прежнему открывает пользовательскую базу: для этого эксперимента используйте явный `--db`.

## Единый редактор постоянного графа (M018)

В постоянном графе нажмите **«Редактировать граф…»**. Здесь можно создать концепт или α, отношение/обязательный компонент и контекстную пару, выбрать существующий узел либо открыть любой объект по ID. То же действие «Изменить общий объект…» доступно в меню узла/ребра/контекста обоих полотен. Формы редактируют общие ID сразу после preview и отдельного подтверждения; повторно публиковать незатронутые определения не требуется.

Для α выберите обязательные компоненты по существующим IDs. Имя необязательно. Переход α в concept требует явно убрать компоненты; пустая опубликованная α, цикл и повтор компонента запрещены. Relation и component имеют разные функции. Контекст выбирает только ID обычных рёбер; изменение концов ordinary ребра сохраняет его ID и адресующие его пары. Смысл контекста после правки пересматривает оператор.

Для локальной подготовки выберите узел и глубину окружения, затем **«Область → миниграф»**. Можно также открыть «Редактировать граф… → Выбрать узлы области…», отметить произвольные IDs и воспользоваться поиском. Текущий черновик сохраняется отдельно. В области доступны прежние поля, характеристики, состав α, соединение узлов, маршруты и контекст. **«Применить область…»** показывает изменения общего графа и требует подтверждения. Сохранение незавершённой области не меняет постоянные объекты.

Чистая сохранённая область автоматически обновляется после общей правки в этой вкладке. Незавершённая или устаревшая показывает предупреждение и не может перезаписать свежие данные. Нажмите **«Открыть актуальную область…»** и перенесите нужные правки вручную; старый текст и структура сохраняются в прежнем черновике. В другой вкладке обновите страницу для получения новых данных. Не закрывайте вкладку с несохранённым текстом до сохранения: браузер предупреждает о нём. Для старого повторно выбранного ID доступно прежнее явное обновление после просмотра; собственные внешне изменённые объекты требуют актуальной области.

Для контрольного преобразования «деталь → часть»:

1. Найдите существующий ID «часть» и постройте вокруг него нужную структуру в общем графе либо области. Используйте существующие ID, где это выбрано оператором; отдельная α на слово не требуется.
2. Откройте исходную «деталь» → **«Все использования / преобразование…»**. Форма показывает обычные отношения, компоненты α, определения, контекстные пары, обозначения и неподтверждённые черновики. Родительские α и определения, использующие исходный ID через вложенный обязательный состав, показаны отдельно; их собственные ID не перенаправляются автоматически.
3. Выберите target ID «часть». Отметьте нужные концы рёбер и прямые включения в определения. Можно перенаправить одно использование или весь выбранный набор одним действием.
4. Отметьте обозначение «деталь» для перепривязки: сохраняется его ID и источник, меняется только target. При необходимости отметьте удаление исходного концепта. Оставшиеся зависимости заблокируют удаление.
5. Просмотрите до/после, все ID, индексы определений, контекст и предупреждения о черновиках; подтвердите применение. Рёбра сохраняют прежние ID, незатронутые определения не открываются и не перепубликуются.
6. Если смысл требует изменения контекстной пары или обычного отношения, откройте их по ID. Автоматической проверки семантической эквивалентности нет; структурно некорректное преобразование отклоняется целиком.

Удаление общего узла с зависимостями открывает отдельный список. Явно отметьте удаляемые отношения, компоненты, контекст и обозначения, затем просмотрите результат. Невыбранная зависимость или опустевшая α блокирует операцию. Незапрошенных каскадных удалений нет. Для комплексной замены используйте перенаправление, сохраняющее ID рёбер. Удаление обычного ребра с контекстом без обработки пары запрещено; в области можно явно убрать пару и ребро одной подтверждённой правкой.

«Данные и история» экспортирует весь граф, черновики и историю в JSON. Полное восстановление версии заменяет всё состояние этой версией, сохраняя историю позднейших действий; это не выборочная отмена отдельной операции. Импорт в чистую базу восстанавливает точный state, конфликтный импорт в непустую по-прежнему отвергается. Лимиты области: 80 узлов / 160 рёбер / 800 пар, до 20 сохранённых черновиков. Неизменённая область того же набора открывается повторно с прежним ID. Проверки и ограничения — [M018](composition-verification.md#m018-единый-редактор-постоянного-графа-15-октября-2026).


## Квадраты обычных рёбер и контекст (M017)

В середине каждого видимого обычного ребра теперь есть небольшой квадрат — элемент интерфейса для его прежнего ID. У component квадратов нет. Hover или клавиатурный фокус подсвечивает соответствующее ребро и его контекстные связи. Щелчок/Enter выбирает квадрат; Ctrl/Shift добавляет или снимает выбор. Правый щелчок/Shift+F10 открывает прежнее меню ребра.

Переключатель «Маркеры» на полотне показывает все квадраты, только выбранные или скрывает их для обзора. Чтобы выбрать ребро при скрытых квадратах, используйте обычную линию и затем режим «Выбранные». Скрытие квадратов не удаляет контекстные линии или данные. Настройка сохраняется локально вместе с видом полотна.

Нажмите «Контекст →», затем квадрат источника и квадрат назначения. В конструкторе откроется «Маршруты и направленный контекст» с выбранными ID: нажмите «Добавить контекст →». В постоянном графе сначала предлагается выбрать те же ID в текущий черновик; подтвердите этот выбор, добавьте пару и выполните обычное «Включить в граф…» с preview. Концепты и ordinary рёбра повторно используются без копирования. Escape на полотне или повтор кнопки отменяет выбор пары. Прежнее действие «Контекст отсюда →» в меню ребра также работает с квадратом назначения.

Фиолетовый пунктир со стрелкой идёт между квадратами и перестраивается после движения любого узла и раскладки. Путь может быть прямым, диагональным или сглаженным; он обходит видимые concept/α, включая круглые узлы M015. «Не проложено» означает закрытую середину ребра, совпавшие маркеры или недоступный обход в текущем лимите. Маркер при этом не перемещается в другую точку. Измените расположение либо откройте связь по ID через «Маршруты и контекст» / «Действия → Контекстные связи по ID…». Невидимые и сверх лимита пары посчитаны отдельно. Наложения самих линий остаются возможными; список ID позволяет выбрать конкретную пару и развернуть/удалить/отредактировать её независимо от геометрии.

## Выбор существующего концепта по происхождению (M016)

В «Добавить поле» найдите слово или UUID. Под каждым существующим ID перед «Использовать этот ID» показаны сохранённый текст разбора, породившего узел, текущее название определения и его источник. Совпадающее обозначение не устанавливает тождество: сравните контексты каждого ID. Список результатов прокручивается; длинный текст сокращён до 360 символов и раскрывается через «Полный текст определения».

Раскройте «Опубликованные контексты использования ID»: определение создания (текущая версия) и «Повторное использование ID в другом определении» различены. Например, использование «детали» в определении «винта» показывает контекст разбора винта, а не новое самостоятельное толкование детали. Сохранённые черновики доступны отдельно и явно не подтверждены. «Окружение и происхождение» открывает те же сведения, читаемые обозначения/источники значений, связи и контекстные пары; в постоянном графе это доступно из формы концепта по одноимённой кнопке.

«Источник определения не указан», «Текст определения отсутствует» и «Происхождение отсутствует» означают отсутствие соответствующего свидетельства. Источник значения словарного обозначения не подставляется вместо источника определения. Название отмечено как текущее, если историческое название не сохранено. Повторная публикация теперь сохраняет имеющийся снимок создания, текущий опубликованный текст показан отдельно. У старых данных ранний снимок мог быть перезаписан прежними публикациями; интерфейс показывает сохранённый текст без реконструкции. Чтение/раскрытие не записывает граф; reuse сохраняет выбранный UUID.

## Обзор постоянного графа и раскладка (M015)

В постоянном графе concept показан синим кружком, α — фиолетовым. Чем больше инцидентных relation/component рёбер, тем больше круг; радиус ограничен. Сплошные обычные стрелки, пунктир обязательного состава и фиолетовый направленный контекст между рёбрами сохраняют прежние функции. Конструктор остаётся подробным прямоугольным миниграфом.

Названия появятся при наведении, клавиатурном фокусе или выборе; двойной щелчок/Enter или «Действия → Обозначения и свойства» открывают объект с полным UUID. Подпись безымянной α вычисляется как в M014. Переключатель «Подписи»: «Автоматически» показывает названия при приближении и убирает при отдалении, подавляя часть накладывающихся текстов; «Всегда» показывает все (наложения возможны); «Скрыты» оставляет названия наведённых/выбранных/найденных объектов. Шрифт подписи сохраняет экранный размер; между порогами масштаба auto сохраняет прежнее решение. Настройка локальная и не требует записи в базу.

Поиск сразу выделяет найденные круги и приглушает остальную структуру. Найденные подписи видны даже в режиме «Скрыты». Сначала идут exact ID/designation/вычисленная строка, затем собственные частичные и затем компонентные совпадения. Это визуальный поиск, не семантическая активация. Выбор результата центрирует нужный ID; Ctrl+F5 после обновления клиента загружает новый вид.

1. Нажмите «Раскладка», выберите иерархический, силовой или радиальный режим. Радиальный строится от выбранного узла.
2. Выберите весь граф либо окружение выбранного ID на текущую глубину. Весь граф включает и не нарисованные из-за лимита узлы; локальная раскладка сохраняет все внешние позиции.
3. Настройте зазор и нажмите «Предпросмотр». Worker вычисляет независимо от базы; панорама, масштаб/поиск остаются доступны. Перемещение узлов в preview отключено. «Отменить предпросмотр» отбрасывает результат; во время вычисления эта же кнопка останавливает Worker. Переход к конструктору также отменяет preview.
4. Просмотрите круги/стрелки и нажмите «Применить…», поставьте флажок подтверждения. Координаты сохраняются одной версией; ID/состав/обозначения не меняются. Устаревший preview требует пересчёта.
5. «Действия → Закрепить узел» исключает этот ID из автоматического перемещения; пунктирная обводка отмечает pin. Открепление — то же меню. Закрепление сохраняется в SQLite/export. Явное ручное перемещение закреплённого узла допускается.
6. «Вернуть раскладку…» возвращает только предыдущие координаты, сохраняя более поздние правки обозначений и историю. Если затронутые позиции/закрепление уже изменились, быстрый возврат отклоняется. Общая история остаётся доступна; её восстановление меняет весь граф и требует отдельного подтверждения.

Автоматическая раскладка никогда не запускается при публикации. На полотне до 2000 кругов/6000 рёбер; количества показанного/всего указаны. Наложения исходных кругов и невозможные контекстные трассы явно посчитаны. Перекрывающиеся закреплённые круги нужно открепить/переместить или изменить область. Контекстные IDs доступны через «Действия → Контекстные связи по ID», включая пары вне вида/сверх бюджета. Сам граф не обрезается лимитами отображения. Раскладка разделяет круги, но не гарантирует отсутствие пересечений всех линий; для подробного исследования помогают локальное окружение и ручные позиции.

## Вычисляемые подписи безымянных α (M014)

Вместо UUID безымянная α показывается по обязательному составу: `{Стержень, Головка}`; вложенная — `{Деталь, {Стержень, Головка}}`. При наличии собственной словарной формы показывается первая форма, например «Винт». Новая α без выбранных компонентов временно подписана «α · состав ещё не задан». Сначала выводятся обычные концепты, затем вложенные α; состав в графе от этого не меняется.

Эти подписи одинаково используются в миниграфе, общем графе, результатах поиска, меню, формах полей и выбора компонентов. Изменение состава обновляет подпись черновика и его родителей сразу после сохранения состава; общий граф обновляется после включения. Изменение designation опубликованного компонента сразу обновляет подписи его α. Поиск «Головка» находит также безымянные α, содержащие головку на вложенных уровнях; учитываются все обозначения компонентов. В поиске конструктора/общего графа можно ввести и саму вычисленную строку или короткий #ID. Поиск существующих ID в конструкторе относится к опубликованному графу, а не к ещё не включённым новым α.

Разные α с одной подписью сохраняют разные ID: в списках добавляется #токен, на полотне у каждой безымянной α короткий ID виден в нижней строке. Форма объекта, дерево состава, списки выбора и переключатель ID дают полный UUID. Совпадение текста не объединяет конструкции. Наведите указатель на поле для полной вычисленной подписи, откройте свойства для дерева/обозначений компонентов. Длинная подпись сокращается многоточием: максимум 12 уровней/256 раскрытий/512 символов, поиск по составу — 20 уровней/2048 различных ID; дерево M013 — 20 уровней/200 строк. Через конкретный ID компонента можно просматривать дальнейшее окружение и реальные обозначения. Эти границы не обрезают сохранённый граф.

Подписи не записываются в словарь или базу; после restart/import они вычисляются заново. Для обновления клиента сохраните черновик, перезапустите сервер и обновите страницу (Ctrl+F5). Прежние v2 exports подходят без преобразования.

## Вложенные α (M013)

В «Добавить поле» можно создать обычный концепт или нажать «Создать α (обозначение необязательно)». Внешнее обозначение новой α можно оставить пустым: её адрес — собственный ID. Название определения относится к рабочему черновику, а не к α.

1. В определении α₂ создайте α без названия, «Стержень» и «Головка». Откройте α через правое меню «Обозначения и свойства» либо «Действия → Поля и рёбра по ID». Нажмите «Редактировать обязательные компоненты», отметьте стержень/головку, сохраните состав, просмотрите и включите миниграф.
2. Создайте новое определение. Добавьте α₁ и «Деталь»; через поиск по полному ID или постоянный граф выберите α₂ кнопкой «Использовать этот ID». В составе α₁ отметьте только деталь и α₂. Вложенность останется α₁(Деталь, α₂(Стержень, Головка)). Публикация не копирует α₂ или её компоненты.
3. Через «Добавить обозначение» у α₁ привяжите «винт». Для опубликованного ID это отдельная запись общего графа и истории. α₂ может оставаться без словарного названия.
4. Обычная команда «Соединить отсюда →» добавляет отношение к выбранному ID. Отдельно соедините α₁ с характеристикой целого, головку — с завинчиванием. Компонентность задаётся только редактором состава; она показана фиолетовым пунктиром и не включается в маршруты/контекст. Связи головки не переносятся на α₁.
5. В форме α видно дерево состава с полными ID; в общем графе оно отражает опубликованное состояние, в конструкторе — текущий черновик. Собственные kind/notes задаются кнопкой «Редактировать собственные характеристики» и необязательны. Для изменения α₂ откройте её исходное определение; снимите/добавьте прямые компоненты и снова подтвердите включение. Для новой конструкции повторно выберите тот же ID α₂.
6. «Данные и история» экспортирует v2 со всей историей. Перезапуск с той же SQLite продолжает работу; GUI-импорт в чистую изолированную базу сохраняет IDs/вложенность и архивирует полную историю источника. v1 без α также читается. Восстановление прежней локальной версии создаёт новую запись истории.

Изменённый повторно выбранный объект требует просмотра и кнопки «Обновить выбранный ID после просмотра», затем публикации. Чужие подтверждённые ссылки защищены от удаления. Пустую α можно сохранить как черновик; публиковать её, создавать циклический состав или повтор компонента нельзя. Обязательные включения не являются упорядоченными позициями/множественностью.

Показ дерева ограничен 20 уровнями/200 строками с явным сообщением; хранение не обрезается. Геометрия обычных/компонентных линий прежняя: при перекрытии переместите поля и используйте выбор по ID. Для открытия свойств воспроизводимо используйте меню/«Действия»: двойной щелчок на SVG в проверке не открыл форму. Старая версия приложения v2 не поддерживает; эксперимент проводите на отдельной базе, сохранив исходную копию.

## Рабочие области

В компактной верхней панели выберите **«Конструктор определений»** или **«Постоянный граф»**. Отображается только выбранная область на всю ширину: конструктор работает с миниграфом текущего определения, постоянный граф — с общим полотном и окружением. Выбор запоминается в этом браузере. Переключение сохраняет введённый текст и положение миниграфа в открытой странице, но не записывает несохранённый текст в SQLite: перед закрытием/reload используйте «Сохранить черновик».

Из общего графа кнопка **«Использовать ID в черновике»** возвращает в конструктор с выбранным ID. Сведения о проверенной резервной копии прежней SQLite, её скачивание, импорт/экспорт, история и диагностика доступны в **«Данные и история»**. Постоянного уведомления о резервной копии над рабочим пространством нет.

## Словарные обозначения выбранного поля

Двойной щелчок по полю или правый щелчок → **«Обозначения и свойства…»** открывает форму с ID и **«Словарные обозначения · точки входа»**. Можно сразу после создания «деталь» нажать **«Добавить обозначение»** и ввести «гайка». У другого ID, например «птица», можно добавить ту же «гайка»: поиск предложит оба ID, источники и **«Окружение и происхождение»**. Выберите **«Использовать этот ID»** вручную. Это входы в концепт, а не автоматическая синонимичность слов.

В диалоге обозначения нажмите **«Получить значения слова»**, затем **«Связать с этим значением»**: сохранится статья/омоним, номер значения, источник, редакция, исходный текст и условия использования. Доступны ручные поля источника и **«Убрать источник значения»**. Нет сети/толкования — остаётся ввод слова и собственного источника. Получение значения в этом диалоге не заменяет исходное определение миниграфа.

**«Изменить»** правит только выбранное соответствие с сохранением его ID; **«Удалить» → «Удалить соответствие»** удаляет его без удаления концепта, остальных обозначений и рёбер. После удаления всех обозначений поле показывается по ID. Новые поля и их обозначения остаются черновиком до подтверждения включения. Для уже включённого ID правка обозначения сразу сохраняется в общем графе и истории; повторное включение старого определения её не отменяет. Все обозначения видны у поля независимо от определения, создавшего концепт. Экспорт переносит соответствия и источники вместе со структурой и историей.

## Работа непосредственно на полотне

Обычный `start.cmd` открывает одно приложение с двумя переключаемыми областями. В конструкторе отображаются миниграф и короткая строка команд; нижних таблиц полей/рёбер/маршрутов нет. Все подробные формы открываются поверх полотна и прокручиваются внутри своего окна.

```bat
cd /d E:\Projects\concept-field-lab
start.cmd
```

Нужны Python 3.11+ и браузер; npm/pip/сборка не нужны. Адрес `http://127.0.0.1:8765`, SQLite по умолчанию `local-data\workspace.sqlite3`. Отдельная база: `start.cmd --db local-data\my-input.sqlite3 --port 8766`. Остановка Ctrl+C; следующий запуск продолжает сохранённый граф. После обновления интерфейса M011 сохраните открытый черновик, перезапустите `start.cmd` и обновите страницу Ctrl+F5: сервер должен подключить новые файлы меню/форм.

1. Нажмите **«Определение»**, введите название/текст и **«Сохранить определение»**. Либо откройте **«Добавить поле»**, найдите лемму и выберите **«Взять это определение»** у нужного словарного значения. Толкование сохраняет происхождение в черновике и не создаёт концептов автоматически. Без сети доступны локальные формы/cache и собственный текст.
2. Через **«Добавить поле»** или меню свободного места **«Добавить поле / найти ID…»** найдите лемму, обозначение или ID. Существующий ID выбирается явно; **«Создать отдельный концепт»** у словарной формы либо ручной ввод обозначения создаёт новый ID. Одинаковое слово не объединяет узлы. На уже заполненном полотне новое поле ставится в выбранную точку; поля можно перемещать мышью.
3. Правый щелчок по узлу открывает обозначения/происхождение/соединение/удаление из миниграфа. Двойной щелчок открывает форму обозначений. Несколько слов и значения можно привязать одному ID, одно слово — разным IDs. При уже включённом ID отдельная правка обозначения сохраняется сразу; структура графа остаётся прежней.
4. Для обычного ребра выберите у исходного узла **«Соединить отсюда →»**, затем щёлкните конечный узел. На панели появится указание текущего выбора; Escape или «Отменить выбор» отменяет операцию. Если ребро уже существует, форма предложит его ID либо обоснование нового параллельного. Старый ID при reuse сохраняется.
5. Правый щелчок по ребру → **«＋ В выбранный маршрут»** набирает последовательность. Кнопка **«Подтвердить маршрут»** или соответствующая команда меню покажет пары каждого ребра ко всем последующим внутри этой последовательности. Только после подтверждения они записываются в черновик. Каждая ветвь подтверждается отдельно; автоматических пар между ветвями нет.
6. Контекст виден прямо на полотне фиолетовым пунктиром: стрелка идёт **от одного обычного ребра к другому**, квадраты отмечают фиксированные середины обычных рёбер (M017). Гибкая линия обходит поля и пересчитывается при их перемещении; «Вписать» включает её целиком. Щёлкните пунктир для формы пары; правое меню открывает ту же форму, где можно развернуть или удалить связь. Для ручной пары выберите у исходного обычного ребра **«Контекст отсюда →»**, затем другое обычное ребро. **«Маршруты и контекст»** открывает списки сохранённых маршрутов/пар и выбор по ID; пару можно добавить, удалить или развернуть. Удаление записи маршрута не удаляет его контекст. Легенда показывает количество видимых пар. «Не проложено» означает закрытый/совпавший маркер или недоступный обход в текущем лимите: переместите поля либо откройте пару в списке. «Вне вида» означает, что одно из обычных рёбер скрыто окружением. При перекрытии объектов используйте меню **«Поля и рёбра по ID…»**, чтобы открыть объект или выбрать конец текущей операции.
7. Нажмите **«Включить в граф…»**, просмотрите изменения/IDs, отметьте подтверждение и нажмите **«Включить в граф»**. Это единственное применение структурных изменений черновика к общему графу. Удаление поля/ребра из миниграфа сначала сохраняется только в черновике; чужие подтверждённые ссылки защищены. Повторное включение не создаёт копий и не сбрасывает независимые обозначения.
8. В **«Постоянный граф»** контекстные стрелки показываются так же. Меню **«Контекстные связи по ID…»** доступно через «Действия» или правый щелчок; список ищет по ID пары/обычного ребра и открывает инспектор даже при скрытой трассе. Ищите обозначение/ID, перемещайте полотно и инспектируйте объекты через правый/двойной щелчок. Меню узла предлагает окружение и **«Использовать ID в миниграфе»**. **«Редактировать в конструкторе»** открывает черновик происхождения для структурных правок/контекста; они вновь требуют preview и подтверждения. Окружение показывает связность общего графа, а не автоматически выбранный допустимый маршрут.

Кнопка **«Действия ▾»** открывает то же меню для выбранного объекта; Shift+F10 / клавиша меню — для сфокусированного SVG-объекта. Tab перемещает фокус, стрелки — внутри меню, Escape закрывает меню/отменяет текущий выбор. Отдельные формы сохраняют доступ к операциям без правой кнопки мыши. Список сохранённых определений и **«Новое»** переключают черновики; приложение продолжает ручную работу, без определения смысла по контексту или активации.

Операции с полями/рёбрами/контекстом сохраняют черновик в SQLite. Текст определения сохраните в своей форме до закрытия страницы. Изменения текущего текстового черновика остаются в памяти открытой страницы при закрытии формы и переключении вида, но не после reload без сохранения. Источники и IDs доступны в формах. Старый редактор исследований для этого не нужен.

## Данные и история

Кнопка **«Данные и история»** открывает служебный диалог, а не третью рабочую область. Экспорт/резервная копия JSON включает весь постоянный граф, черновики, происхождение, локальную историю и архив полученной истории импорта. Импорт: выберите этот JSON, просмотрите изменения, подтвердите. Он добавляет отсутствующие IDs, пропускает точные повторы и целиком отклоняет конфликты. Совпадение текста не объединяет концепты. Входные отсутствующие объекты не удаляют существующие; изменение уже введённого выполняйте в конструкторе. История позволяет явно восстановить весь граф из собственной версии, сохраняя более поздние строки журнала. Диагностика показывает режим, путь базы и резервного сохранения.

[Формат постоянного графа](data-format-permanent.md) — `concept-field-permanent` v1. Старые `concept-field-graph` v1–v4 новым режимом не импортируются: чтобы не перенести исторические исследования автоматически, открывайте их отдельно.

## Безопасное открытие старой SQLite

При первом обычном запуске со старой базой приложение сначала делает SQLite backup **всей** базы (включая WAL), проверяет integrity_check и совпадение SQL-содержимого, сохраняет SHA-256 и JSON-манифест в `local-data\backups\`. Только после успеха создаётся пустой постоянный граф в новой таблице; прежние данные `revisions` не изменяются. Если резервная запись/проверка невозможна, переход прекращается с ошибкой, новая таблица не создаётся. Исторические K001/K002/K003/полотно не появляются в активном графе.

В «Данные и история» находятся сообщение о сохранении прежней базы и путь/проверки копии. Кнопка «Скачать проверенную старую SQLite» выдаёт отдельный backup. Сохраните его вместе с JSON-манифестом; проверка файла в PowerShell: `Get-FileHash -Algorithm SHA256 <путь-к-копии>` и сравнение sha256 с манифестом. После первого перехода новые открытия продолжают постоянный граф и не создают повторный backup.

Для просмотра/восстановления исторических данных сделайте **отдельную рабочую копию** резервной SQLite, оставив оригинальный backup нетронутым:

```powershell
Copy-Item -LiteralPath 'local-data/backups/<имя-backup>.sqlite3' -Destination 'local-data/legacy-recovered.sqlite3'
python -m app.server --legacy --db local-data/legacy-recovered.sqlite3 --port 8766
```

Явный `--legacy` открывает прежний редактор. [Историческая инструкция](legacy-user-guide.md) описывает его исследования, накопление и обмен. При отсутствии резервного перехода старые Git-артефакты можно импортировать именно туда; из него они не переходят в новый граф. Содержимое backup не редактируйте напрямую: это проверяемый исходный снимок.

## Границы

Сохраняются пределы M007: 20 черновиков, каждый до 80 полей / 160 обычных рёбер / 800 контекстных пар / 40 маршрутов по 40 рёбер. Основной граф показывает до 1000 узлов / 3000 обычных рёбер и прокладывает до 800 видимых контекстных пар за проход; сложный обход ограничен 40 000 вершинами сетки и при отказе явно посчитан. Пересечения линий между собой не устраняются; поиск охватывает полные данные. Служебный список последних локальных версий ограничен 80 строками, полная история есть в экспорте. Вход JSON до 64 МиБ. История растёт; автоматическая очистка не выполняется.

Толкования — внешний источник под CC BY-SA 4.0; [происхождение и условия](../../data/dictionary/NOTICE.md). Локальный индекс OpenCorpora остаётся фиксированным снимком 2022 года. Ошибки сети или изменение разметки Викисловаря могут оставить только кэш/ручной текст. Не реализованы активация, сцены, автоматический выбор смысла/маршрута или новая онтология.


## Сценические элементы после UX Correction

Выделите «Винт» в исходном тексте → «Действия с фрагментом» → «Выбрать элемент и содержание». В элементе конструкции выберите назначенную оператором роль или создайте новый безымянный концепт с alias «Объект». В содержании выберите концепт «Винт» либо явно создайте его. Подтвердите компактное «Создать: Объект → Винт». В сцене появляется один `Винт (Объект 1)`. Для «упал» аналогично создайте `Падение (Процесс 1)`. Роли не встроены в программу: список учитывает только явные назначения и прежние структурные применения. Для уже существующего безымянного концепта очистите поиск содержания; назначение существующего концепта ролью находится в раскрываемой части формы.

Выберите первый узел → «Соединить…» → второй узел. Выберите существующее обычное ребро Объект → Процесс либо подтвердите создание недостающего. Привязка Объект → Винт остаётся реальной связью постоянного графа и отдельным использованием, но не создаёт второй сценический узел. Её включение и контекстная активация доступны из инспектора/подробных операций.

Щёлкните размеченное слово, чтобы изменить или снять основную привязку. Тождественное назначение повторно не предлагается; повторное сохранение не создаёт экземпляр. «Создать другой независимый экземпляр» — отдельная команда. «Тот же сценический экземпляр» предлагает поиск с явным выбором существующего объекта текущей сцены; его ID и номер сохраняются. Снятие последнего упоминания из текущего разбора убирает этот локальный элемент и зависимые отношения/разрешения; ранее завершённые мысли остаются в истории. Для обязательной структуры выбранного шаблона сначала используйте «Начать явное уточнение структуры» в подробных операциях.

В одной сцене два разных винта — Объект 1/2, следующий предмет — Объект 3 независимо от содержательного концепта. В новой сцене номера начинаются заново. После удаления всех данных о её элементах браузерный счётчик не продолжает старую нумерацию; неизменённый экземпляр сохраняет свой номер.

Размеченный текст и граф находятся вместе в верхней части поля, компактный инспектор — справа. Полнота, история, редкие операции и ID раскрываются по необходимости. Снимок требуемых двух элементов не означает, что фрагмент «на пол» уже разобран: представьте его отдельно (например, Пол в ещё одном элементе) до подтверждения всего содержания. Завершение в динамической сцене и необязательное включение в knowledge работают как прежде. Для сохранённых неоднозначных старых шаблонов приложение предлагает ручное уточнение, сохраняя оригинал.
