# Проверка M001: ручной инструмент и обмен графами

Этот отчёт фиксирует исходный M001. Последующее расширение и повторные регрессии — в [проверке M002–M003](composition-verification.md).

Дата: 9 октября 2026. Ветка: `codex/manual-knowledge-tool`, основа `origin/main` = `4077ac66ceba23ba64b4cf0af6e158102e63568c`. Цель / граница и предел ресурсов — в [плане](implementation-plan.md). Проверяется работа инструмента, а не истинность семантических карточек.

## Условия и исходные материалы

- Windows 10 build 19045; Python 3.13.2, SQLite из стандартной библиотеки Python.
- Node.js 24.19.0, Playwright 1.62.1 из доступной локальной среды; установленный Chrome 154.0.8037.98, headless. Эти зависимости нужны только браузерному тесту.
- Малые данные генерируются `python -m scripts.fixtures`: два независимых графа по 5 узлов / 5 отношений, включая цикл. SHA256 `data/fixtures/manual-example.json`: `b02fa93a418fc4421047d8d4c2bb457b4e81f1e7ed39a158d2a34950f4458f75`. Это синтетическое содержание, созданное для теста, без внешних источников и подтверждения смысловой истинности.
- Масштабный граф генерируется `scripts.fixtures.large()`: 5 000 детерминированных UUID5-узлов, 10 000 отношений (кольцо и повторное использование со сдвигом 17), свободные тестовые типы. Полный файл и временные базы возникают в `test-output/`, исключённом из Git; генератор, параметры и критерии находятся в репозитории.
- Браузерный тест сам создаёт свои малые исследования через GUI, с UUID4. Записи изменяются через формы / кнопки; HTTP используется для чтения состояния и проверки результата. Созданные базы, снимки и загруженные JSON не изменяются вручную.
- ChatGPT не вызывается: тестовый пакет имитирует предложение изменения и проверяет независимый путь рассмотрения. Семантические решения в тесте явно помечены как синтетические.

## Команды воспроизведения

Из корня репозитория, cmd.exe:

```bat
python -m unittest discover -s tests -v
python -m scripts.fixtures
python -m scripts.benchmark_workbench
python -m compileall -q app scripts tests
node --check app/static/app.js
node tests/cmd-launch.cjs
git diff --check
```

Для полного браузерного сценария нужны Node.js, Playwright и Chrome. Если Playwright ещё не доступен локально, можно установить **только тестовую** зависимость:

```bat
npm install --no-save --package-lock=false playwright@1.62.1
node tests/browser-scenario.cjs
```

В фактическом запуске использовалась уже установленная библиотека, без скачивания:

```bat
set "NODE_PATH=C:\Users\infarh\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\node_modules"
node tests/browser-scenario.cjs
```

Приложению Node.js / Playwright / npm не требуются. В тесте браузера используется порт 8876, в проверке cmd.exe — 8877; они должны быть свободны. Тесты запускают и завершают свои процессы. `BROWSER_CHANNEL=msedge` позволяет вместо Chrome использовать установленный Edge; эта комбинация в данном отчёте не проверена.

## Наблюдаемые результаты

**24 теста Python прошли** ([журнал](evidence/unit-tests.txt)). Они проверяют:

- независимые ID одноимённых исследований; рекурсивное раскрытие, повторное использование и цикл;
- ручные решения, запрет объединения отклонённой пары, выбранное объединение и полные исходные снимки;
- транзитивное объединение нескольких пар и many-to-many diff без потери соответствий;
- постоянное хранение, восстановление истории, защиту корня, обратимое архивирование и stale revision;
- полный round-trip исследования с исходными ID, атрибутами и импортированной историей;
- фрагменты глубины 0 / 1 / 2 / all, импорт фрагмента обратно без смены корня и изоляцию чужих архивов;
- отдельные новые / изменённые кандидаты, повторный импорт, отклонение, конфликт `base`, ID-коллизию и запрет одновременного принятия двух версий объекта;
- отсутствие частичного применения ошибочного пакета и сохранение уже принятого происхождения;
- сброс устаревших соответствий при изменении структуры; все атрибуты в версионном diff и его пакет кандидатов;
- JSON Patch: добавление, удаление, изменение, перестановку, экранирование путей, полное восстановление, повреждённые пути / кодировку и несовпадение итогового состояния;
- HTTP-проверки loopback Host, локального Origin, session token, ошибок и перезапуска.

**Настоящий браузерный сценарий прошёл** ([машинный отчёт](evidence/browser-report.json)). Операторские действия создали «камень» и «камня», рекурсивное пояснение и цикл, затем подтвердили пару свойств, отклонили пару форм, создали объединение и проверили сохранение обоих исходных пояснений. Выполнены экспорт исследования и diff, копирование связного фрагмента, повторный импорт без дублей, просмотр / принятие имитации ChatGPT, явное разрешение конфликта и отклонение нового узла. Через GUI восстановлена ранняя версия и возвращена более поздняя. После завершения одного процесса сервера запущен другой с той же базой; состояния совпали, редактирование продолжилось.

В том же браузере загружен файл 5 000 узлов / 10 000 отношений, приняты 15 001 кандидат одним пакетом, найден «Элемент 4999», показано ограниченное окружение. Этот участок занял **4.299 с**, критерий <30 с. Проверены ограничение DOM (≤180 графических узлов, ≤80 строк списка), сохранение черновика при отмене перехода и отсутствие горизонтального переполнения при ширине 1 000 px. Ошибок JavaScript / console нет. Визуально проверены снимки [редактора](evidence/editor.png), [сопоставления](evidence/comparison.png) и [большого графа](evidence/large-graph.png); узлы и поля читаемы, отличия / решения видны, элементы управления доступны. Пересечения подписей рёбер в плотном окружении возможны; полные отношения доступны в карточке.

**Windows cmd.exe проверен отдельно** ([отчёт](evidence/cmd-report.json)): реальный запуск `start.cmd --no-browser --port 8877 --db "<путь с пробелами>"`, успешное чтение пустой базы через HTTP и завершение только собственного дерева процессов. ## Отрицательные результаты и исправления

Первый запуск выявил незакрытые SQLite connections на Windows: контекст SQLite сам выполняет commit / rollback, но не закрывает connection. Исправлено отдельным контекстным менеджером с `close()`; тесты больше не выдают ResourceWarning / WinError 32.

При первом большом принятии выявлено переиспользование переменной имени коллекции при заполнении полей нового узла. Исправлено; дополнительно проверено успешное принятие новых узлов и отношений. Сравнение кандидатов / объектов индексировано по ID, чтобы избежать квадратичных проходов.

Браузерный тест сначала читал clipboard до завершения асинхронной записи; теперь ожидает её завершение. Отсутствующий favicon вызывал console 404; добавлен локальный SVG. Эти ошибки не скрываются фильтром итогового отчёта.

Полные снимки в первоначальном JSON экспорте слишком быстро увеличивали файл на крупном графе. Принято компактное представление истории через JSON Patch; тест после 20 сохранений проверяет размер и точное восстановление. В SQLite снимки сжимаются, а экспорт обрабатывает их последовательно без одновременной загрузки всех версий в память.

Первая проверка cmd.exe выявила лишнее экранирование кавычек со стороны Node test launcher. Исправлен способ передачи аргументов тестом (`windowsVerbatimArguments`), затем проверен реальный путь базы с пробелами. Команда оператора и `start.cmd` не требуют специального экранирования кроме обычных двойных кавычек вокруг пути.

## Вывод и ограничения

Проверяемый операторский сценарий выполнен через GUI без изменения кода или ручного редактирования файлов данных. Структуры независимы, смысловые соответствия ручные, происхождение и история сохранены, после перезапуска можно продолжать. Для подготовки / массового обмена есть версионный JSON и отдельные кандидаты.

Длительное человеческое испытание удобства, Firefox / Edge, графы за пределами указанного размера и очень длинная история не проверялись. Предел импорта — 64 МиБ, база растёт с историей; для большего обмена предусмотрены отдельные исследования / фрагменты / пакеты. Процесс читает активное пространство в память; многопользовательская сеть не реализована. Все семантические решения теста синтетические; результаты механики не доказывают знания о словах и не переносятся на прежние исследования проекта.

Checkpoint готовится в рабочей ветке, commit / push проверяются по совпадению HEAD и `origin/codex/manual-knowledge-tool`; merge в main не выполняется. Следующий ограниченный шаг — external review и операторский проход, описанный в `../current-state.md`.
