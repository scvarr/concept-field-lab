# JSON v4: ручной конструктор определений

Расширяет [v3](data-format-v3.md). Экспорт: `format: concept-field-graph`, `version: 4`. Импорт читает 1 / 2 / 3 / 4; признаки нового конструктора в документах с меньшим номером отклоняются, включая историю и changes. Старые документы и SQLite-версии не мигрируются при чтении.

В `study.accumulation` необязательные `definitionDrafts` и `manual`. Отсутствие обоих означает прежнюю модель M005. `definitionDrafts` — список черновиков `{id,title,definition,nodes,edges,contextEdges,routes}`. Поля черновика адресуют выбранные/новые UUID концептов; `existing` явно различает переиспользование и создание. Новый узел имеет внешнее `designation` и необязательный `dictionaryId`. Выбранный узел содержит `base` полного просмотренного объекта. Черновые ID ссылок повторяют ID полотна намеренно; они не создают второй концепт. Новые позиции x/y допустимы в прежнем диапазоне ±100000.

Ребро черновика: `{id,from,to,existing,parallelReason?}`. Новое параллельное ребро при уже существующих концах требует непустого parallelReason. Контекст: `{id,from,to}` с двумя различными ID обычных рёбер, направлением и без повторения пары. Маршрут: `{id,edgeIds:[...]}` — 1–40 различных непрерывных рёбер. Запись маршрута — свидетельство ручного подтверждения; после ручной корректировки контекстных пар она не заставляет пересоздать удалённые пары.

`manual` содержит ровно списки nodes / edges / designations / contextEdges. Подтверждённые объекты имеют `definitionId` сохранённого определения. nodes/edges/designations добавляются к действующей материализации без изменения source.snapshot. Новые узлы: `structure: concept`, `designationOnly: true`, пустые label/kind/notes/alternatives/source, внешний текст в designation; отсутствие смысловой категории намеренно. Происхождение хранит снимок определения / внешний словарный ID. Контексты находятся только в `manual.contextEdges`, а не в study.edges: поэтому прежний обход/геометрия не превращает контекст в концептуальное ребро.

ID новых объектов и переиспользуемых обычных рёбер стабильны при включении и обмене. ID обозначения нового узла получается UUIDv5 от строки `concept-field-designation:<nodeId>` в namespace URL. Исходные IDs копий / origins M005 сохраняются. Preview вычисляет тем же pure prepare, что и commit; запись требует актуальную revision и `confirmed:true`. Ошибка оставляет всю транзакцию без изменений.

Метаданные слоя/черновиков переносятся существующим кандидатом study, материализованные объекты — прежними node/edge/designation. Принятие взаимозависимых кандидатов вместе проверяет всё полотно. Фрагмент накопления по-прежнему не экспортируется: используйте полный study или workspace. Импорт не удаляет отсутствующие элементы автоматически; для синхронизации редактированного полотна в уже содержащую старую версию базу используйте штатный versionChanges diff с явными удалениями и review, либо импорт полного результата в чистое пространство. Старый клиент отвергает номер 4 вместо потери новых метаданных.
