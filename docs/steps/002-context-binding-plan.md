# Шаг 002: приобретение и применение правил связывания

Статус: протокол до измерения целевого качества.

## Вопрос

Можно ли из обучающих наблюдений приобрести явные правила выбора контролирующего участника и применять их в новом конкретном эпизоде, в том числе через несколько вложенных действий? Пример типа задачи: в «X пытается открыть Y» приобретённое правило для «пытаться» переносит X как субъекта «открыть». Пример иллюстрирует постановку, не является экспериментальным материалом.

После шага 001 проверяется именно связывание токенов текущего наблюдения, а не лексическая правдоподобность существительного. H2: приобретённые правила с композиционным исполнением лучше запоминания готовой пары предикатов и нерекурсивного исполнения на новых сочетаниях/глубине. Альтернатива: универсальной эвристики «брать субъект» или «сначала объект» достаточно, лексическое обучение ничего не даёт.

## Данные, помощь и независимость

Те же неизменяемые SynTagRus train/dev/test. Basic UD — вход (леммы, токены, отношения); enhanced UD — наблюдение целевой связи в train и ответ в dev/test, скрытый от механизма при инференсе. Предикат xcomp должен быть VERB, его parent VERB/AUX/ADJ; тестируются отсутствующие в basic дереве субъектные дуги, которые записаны в enhanced. Дополнительно отдельно считать xcomp без enhanced ответа и не превращать отсутствие аннотации в отрицательный факт.

Это supervised приобретение правила из предоставленного структурного наблюдения. Семантические типы отношений, xcomp и границы предиката даёт внешняя разметка. Enhanced UD преобразован из исходного SynTagRus, происхождение каждой субъектной дуги не установлено; проверка согласия с этим слоем не является независимой человеческой проверкой смысла. GSD не размечает DEPS, поэтому не использовать его как ложный отрицательный контроль.

По [определению xcomp](https://universaldependencies.org/u/dep/xcomp.html) открытое дополнение получает субъекта из внешнего аргумента; [enhanced UD](https://universaldependencies.org/u/overview/enhanced-syntax.html) делает эту связь явной. Определение задаёт семейство операторов, но правило конкретного лексического предиката и его счётчики приобретаются только из train.

## Механизм и контроли

Из train для каждого управляющего предиката собираются доказанные золотой связью роли-контроллеры nsubj/obj/iobj/obl. Допускается роль nsubj, заданная enhanced связью parent, если basic субъект отсутствует: это позволяет учить оператор без готовых длинных программ. При неоднозначности ролей тренировочный пример исключается из обучения правила, но тестовое задание не исключается по правильности будущего ответа.

Правило выбирает наиболее частую роль (при равенстве фиксированный порядок nsubj, obj, iobj, obl); для неизвестного предиката — глобальная частая роль. Роль nsubj допускает рекурсивное получение субъекта parent через его собственный xcomp; другие роли связываются с прямыми basic аргументами parent. Предсказания возвращают IDs текущего предложения, не леммы. Несколько подходящих участников дают множество; оценка — точное совпадение множества и micro precision/recall/F1.

Контроли: память роли для точной пары parent–xcomp (неизвестная пара → отказ), глобальное приобретённое правило, «всегда nsubj», «obj→iobj→nsubj», приобретённое лексическое правило без рекурсии, приобретённое правило с рекурсией. Эвристики задаются исследователем и явно отделяются от обучения.

Срезы: новые пары предикатов при известных леммах; хотя бы одна неизвестная лемма; цепочки глубины ≥2; случаи с альтернативными кандидатами; отсутствие золотого ответа. Точный текст train исключается, документы не пересекаются. Рекурсия ограничена 16 переходами с защитой от циклов. Отдельный стресс-тест: переименование IDs участников и перестановка токенов с сохранением графа не должны менять привязку; удаление опорного ребра должно обрывать доказательство.

## Завершение и предел

Без подбора сетки: majority train, фиксированный tie-break и предел глубины. Test оценивается однократно после проверки корректности. H2 подтверждается локально только если новый-known срез содержит ≥100 примеров и превышение памяти пар ≥5 п.п. с положительным нижним bootstrap CI по документам; лексическая польза относительно эвристик и польза рекурсии оцениваются отдельно, без смешения с основным критерием. Для глубокого среза <30 примеров результат считать иллюстративным.

Предел: уже загруженные данные, стандартная библиотека Python, <2 ГБ RAM, <20 минут на запуск, максимум один исправленный запуск после обнаружения технической ошибки с сохранением объяснения. Завершение: правила, входные IDs, связи, трассы, ошибки, категории и все метрики сохранены; ограничения разметки отражены в выводах. При отсутствии пользы менять вопрос, а не расширять test-подбор.
