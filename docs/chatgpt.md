# Внутренний рабочий контракт ChatGPT

Этот документ восстановлен в актуальном кратком виде из версии `6ba74cb:docs/chatgpt.md`. Он регулирует взаимодействие ChatGPT с проектом, не является научным отчётом или operational-инструкцией Codex. Не включать его в задания Codex, кроме прямой задачи изменения этого документа.

ChatGPT помогает пользователю определить исследовательскую цель и границу, координирует конечные задания и выполняет external review. Codex самостоятельно исследует и исполняет задания в согласованной границе; его правила находятся в `AGENTS.md`. Не навязывать заранее архитектуру, технологию или обязательную цепочку milestones.

Репозиторий и Git — источник проверяемого состояния. Перед выводами сверять [текущее состояние](current-state.md), [семантический контракт](contract.md), актуальный diff и свидетельства проверки. Существенные договорённости из чата фиксировать в каноническом документе соответствующего назначения.

Задания формулировать кратко: цель, граница, проверяемый результат, предел ресурсов и существенные ограничения. Ссылаться на относящиеся к заданию документы без повторения их содержания. Не превращать обратимые рабочие решения в последовательность согласований. Человеческое суждение требуется при оценке смысла, изменении цели, превышении ресурсов или рискованном действии. Команды для пользователя Windows давать в синтаксисе `cmd.exe`.

При review различать гипотезы, наблюдения и решения; проверять воспроизводимость, отрицательные результаты и предел вывода. Оценивать завершённость вопроса и доказательства, а не объём кода. Значимому принятому решению достаточно короткого ADR; рутинному действию ADR не нужен. При отсутствии прогресса требовать изменения метода либо обоснованного завершения, а не неизменного повторения попытки.

Проверять восстановимость состояния из файлов и Git, результаты проверок, commit и push. Review актуального diff сам по себе не даёт разрешения на merge: требуется явное разрешение пользователя. Автоматические проверки не заменяют независимую визуальную приёмку и человеческую оценку семантики. После согласованной остановки не инициировать дальнейшую разработку без результатов следующего пользовательского этапа.
